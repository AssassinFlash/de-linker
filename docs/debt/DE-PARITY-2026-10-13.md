## 2. 补缺：没有可导入的缺口

既有机制是 `tools/migrate/9-i18n.py`：从 `_linker_de_title` / `_linker_de_content` / `_linker_de_excerpt` 和词典建德语孪生，经 `wp linker-i18n import`。genieentry 的窄导入记录在 `docs/acceptance/2026-10-12/genie-entry-fix/de-fixture-import.json`（4 个 post，无模型翻译）。

对 t110 只读核对：

- 标题与英文孪生相同、且快照 `_linker_de_title` 又不同的德语商品 = **0**。
- 德语摘要或正文为空、且快照字段非空的德语商品 = **0**。
- 10 个货架分类都已有德语孪生，商品已挂在德语分类上。
- 快照目录（`tools/local` 的 snapshot）只有 `plugins/`、`themes/`、`uploads/`，没有数据库，分类关系不在快照里。

文章分类关系是唯一对拍面的内容缺口，**快照里没有**。线上公开 REST `?lang=de` 返回的仍是英文文章和英文分类 id（`hybrid-inverter-vs-ac-coupled-storage` → category 10），不是可导入的德语分类归属。`tools/migrate/9-i18n.py` 的 `assign_new_term` 只在**新建**德语词项时，把英文词项上已有的文章抄到德语词项；英文词项自己的 count 也是 0，重跑 import 补不出这层关系。没有另写 SQL 去挂分类，也没有造一页。

404 的 `<title>`：`seopress_titles_option_name` 只有一条 `seopress_titles_archives_404_title = Page not found %%sep%% %%sitetitle%%`，不分语言。词典 `linker_i18n_chrome_map` 有 `Page not found` → `Seite nicht gefunden`，但没有既有通道把它写进这个选项。改这一条会连英文标题一起改，所以没改。可见正文两侧都是德语（见 §4）。

## 3. 协议

与 `docs/debt/sources/capture-resume.mjs` 相同：一次 Chromium 启动（读到 `156.0.8078.4`），两侧独立匿名 context，视口 1440×900 / 390×844，URL 带 `cbq`，禁动画，`document.fonts.ready`，滚动触发 lazy，图片 decode 或 15 秒上限，全页 PNG。不跟跳转进另一种语言。

差异：本机系统代理 `127.0.0.1:1082` 让裸 `chromium.launch` 报 `ERR_TUNNEL_CONNECTION_FAILED`。`curl --proxy http://127.0.0.1:1082` 对同一 URL 返回 200，所以启动参数显式写了这个代理，`127.0.0.1,localhost` 不走它。

像素：`python3 .scratch/de-parity/diff.py`，threshold 0，无掩膜，无平移。高度差的像素计入 full，不从重叠区里抹掉。`mag==1` 是重叠区里通道差正好为 1 的比例。

采集中 t110 的 PHP 进程退出过一次（`curl` 到 8975 为 000）。按 `tools/local` 的 `server.start` 只重启了监听，没有 `just up`（`up` 会 `wordpress.refresh`，会动别人正在用的插件 symlink），没有 reset，没有重装快照。断点前已写出的 PNG 保留，其余续拍。

第一轮有 4 张桌面图宽 1630（短页没有滚动条，Chromium 把视口加宽）。这 4 对删掉重拍，重拍前锁 `overflow-y: scroll`。重拍后 56 张 PNG 宽度都是 1440 或 390。

脚本、计数和像素摘要在工作区 `.scratch/de-parity/`（约 80MB PNG，不进本 PR）。可复核的数字是 `docs/debt/analysis/de-parity-2026-10-13.json` 与 `docs/debt/captures/de-parity-dom-counts.json`。
