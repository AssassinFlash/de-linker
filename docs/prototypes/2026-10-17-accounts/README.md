# 原型：后台账户页长什么样（#226，地图 #220）

**一次性原型，不进生产。** 问题：业主一进后台就能找到、一眼看到批准 / 拒绝的独立账户页，应该长什么样。业主的审批方式（2026-10-17）：按注册时提供的信息自己查证，属实就批。

## 三个变体（`/wp-admin/admin.php?page=linker-accounts-prototype&variant=A|B|C`）

三个变体都有：左侧菜单第二项 "Accounts" 带待审数红标；三态操作（Approve / Restrict / Reject，限制与拒绝必须写原因，原因会进客户邮件）；自动检查（VIES 结果、公司域名还是免费邮箱、公司名像不像机器人）；一键查证链接（Google、公司网站、North Data、VIES）；决定后 7 秒内可撤销；通知邮件的链接带 `&focus=<用户ID>` 直达该申请。

| 变体 | 做法 | 适合 |
|---|---|---|
| **A · 列表** | WordPress 原生列表：状态标签（Waiting / Approved / Restricted / Rejected / All）、搜索、每行直接三个按钮、"Details" 展开全部注册信息 | 申请多时一屏看完、批量处理 |
| **B · 审核台** | 左边待审队列，右边一次只看一个申请：注册信息、自动检查、查证链接、"我的核对"三个勾选；决定后自动跳到下一个；键盘 A 批准 / R 拒绝 / J K 上下 | 逐个认真查证（业主现在的做法） |
| **C · 仪表盘 + 顶栏红旗** | 后台首页顶部一个"等你处理"卡片区；后台顶栏常驻红色"N accounts to review"，任何页面点它都弹出侧滑抽屉直接处理 | 不可能错过；处理完不用离开当前页面 |

示例数据（8 个申请，含线上 10-14 那条真实机器人注册），按钮不写数据库。字段沿用现在的注册表单，注册字段研究（#224）定稿后同步。
