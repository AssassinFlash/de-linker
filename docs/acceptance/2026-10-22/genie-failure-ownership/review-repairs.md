## Empty-question codec compatibility

Strict journal validation exposed an existing valid *withheld attachment* state: an attachment-only upstream failure can lose its attachment claim when its bytes cannot be retained, leaving no retryable question text. Rejecting that normalized state would either poison the bucket or prevent the existing failed-turn machine from recording the omission.

The only readable empty-question exception now requires all of:

- A native `owner` with a nonempty string attempt and a 64-character hexadecimal scope.
- `kind='upstream'` and no `editing` flag.
- No prepared upload payload and at least one nonempty omitted filename.

Unknown ownerless v1 stays inactive and byte-identical. Empty editing questions still fail validation.
