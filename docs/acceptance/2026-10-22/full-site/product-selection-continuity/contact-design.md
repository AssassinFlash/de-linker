# Contact selection continuity

The actual German shop-to-Contact readback had a source/title/search URL but an empty Contact context surface. Evidence: `../taxonomy/browser-empty-final-20261021T232740731Z/de-390-shop-contact-consumer.json`. The question textarea was empty, no context element existed, and no submission was made. The archive invitation also dropped its active filters and sort from its href. Its `data-linker-contact` attribute had no active consumer.

## Existing mechanisms used

The current native Contact form posts to admin-post. `FormRecovery` already recovers editable fields and the logical request UUID from the current Woo session; `FormFields` and `Business` own proof, normalized fingerprints, and retry admission. `Sender::message($submission, $meta)` already writes separate metadata before inquiry receive/queue preparation. Woo's native order admin and email-order-meta hooks already expose additional team data, and native privacy erasure accepts extra metadata keys. These mechanisms carry the selection; no parallel submit path, binder, signature API, or email sender is introduced.

The source is a published, unpassworded same-origin product/page/post or a viewable product taxonomy term. Resolve it by native WordPress object and verify its canonical path on initial GET and again on POST. Ignore browser titles, IDs, arbitrary query credentials, fragments and unknown selection keys. Allow only the archive's search/facet/range/sort vocabulary; public selection is customer background, not a product fact or entitlement. Display the canonical current title, a link back to the selected result URL and labelled conditions.

A signature is unnecessary: the context has no authority, private object access, executable URL, mail destination, price or account permission. POST validation resolves current public objects again and rebuilds a same-origin URL from whitelisted fields. Forging another valid public selection has the same semantics as selecting it in the public archive. A signature would add expiry/retry coupling without increasing the authority of this public background.

## Form and submission contracts

- A native checkbox includes the separately displayed selection. Its value is the selection JSON; only checked successful controls enter the native POST. There is no hidden selection JSON. Clearing it hides the summary and displays “This selection will not be sent.” A data-free 0 marker preserves that exclusion state after a failed POST; the removed selection itself is not stored or returned. The full label is a minimum 44px target. The fieldset and selection wrap on narrow screens. This state works without JavaScript.
- The question textarea is not prefilled, appended to or replaced. Existing identity/contact fields and consent are unchanged.
- Revalidation failure for included context blocks the submission before proof/admission/native write. The customer can exclude it and send their unchanged message. Initial invalid structured input remains available for that explicit choice; unsupported older source links do not imply a valid context.
- The included normalized context enters the Contact Business payload and a distinct `_linker_contact_selection` order metadata value before receive. An excluded context enters neither. Unknown browser values are not stored as authoritative titles.
- Selection is a private `Submission` property. Other doors' existing `get_object_vars` payloads retain their original shape. A context-free Contact payload also retains that shape; included context adds one explicit selection key. An inclusion change on a completed logical UUID cannot masquerade as the same semantic request.
- The team email and native order screen read the separate metadata. The unverified customer receipt remains fixed. A native privacy erase removes the metadata, because search text can contain customer input.
- Failed form recovery includes the still-selected transport or a data-free exclusion marker, original message, and logical UUID, but excludes proof, nonce, password and credentials. It remains native Woo once-only five-minute recovery; this work does not invent an extra browser cache.
- Search retains the archive's sanitized text, including values longer than a short Contact identity field. The compact canonical transport must fit the existing native FormRecovery 5000-character field bound (`Submission::MAX_MESSAGE`); an oversized transport is invalid, never silently truncated to another selection. Recovery re-encodes valid context before applying that bound, so ignored browser keys do not corrupt it. Numeric ranges use existing positive finite filter semantics; sort is the existing allowlist. These bounds are normalization, not product facts.
