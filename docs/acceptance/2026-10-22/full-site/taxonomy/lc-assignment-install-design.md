# Native LC product-taxonomy assignments — installer contract

Status: metadata-only implementation candidate frozen for independent review and parent-run native acceptance. The existing empty-archive design and parent readback establish the existing EN/DE product-archive pair (231/6905), the eleven public/queryable product taxonomies, and the empty-loop LC matcher gap. IDs are observations, never source constants.

Use a small data-only `Presentation\ArchiveAssignments` helper. Discover existing registered taxonomies through `get_object_taxonomies('product', 'objects')`, retaining only public and publicly-queryable registrations. Derive LC's generic `is_archive_for_tax_<name>` keys; do not add per-term keys, copy HTML, create another template, change taxonomy registration or alter request matching. Resolve targets through `Templates`' existing English product-archive anchor and `german_twin()` Polylang lookup.

Before assignment writes, inspect all existing explicit generic owners across languages. One published-template query with primed metadata, followed by PHP inspection, avoids a taxonomy-count-dependent OR/JOIN graph. Native LC selects published owners by metadata existence, so even an explicit competing generic value `0` or an empty string is a conflict. Another template in the same language (or an owner whose language cannot safely be classified) refuses the batch with the key/language/template IDs. Draft templates are outside LC's current published matcher and remain untouched. Other-language owners and native per-term assignments remain intact. A second conflict check immediately before the assignment batch prevents a content-sync step from silently changing its assumptions. Missing German twins retain the existing explicit missing-twin report; no substitute twin is created.

`drift()` reports missing generic assignments and owner conflicts using the same discovered keys/targets as `sync()`. A successful sync writes only missing desired `1` assignments, reads them back, and is idempotent. Preflight the complete batch before changing its first key. If an assignment or readback fails, attempt a local rollback of only this batch's target IDs/keys and raise an operator error; a failed rollback must remain explicit.

The existing `PresentCommand` backup additionally saves the exact pre-run values of these keys on the existing owned target IDs, including `[]` for absent metadata, before any assignment write. It remains in the current backup option, not a second persistence channel. The complete option must read back identically before changing templates/settings/assignments. Rollback restores only those saved IDs/keys, preserves complete multi-value lists and slash bytes, verifies actual readback, and consumes the backup only after success. Created templates continue to use the existing created-ID rollback contract; another template is never deleted to resolve assignment ownership. Old backups without the new metadata field stay compatible.

Tests first cover discovery (including unsupported/private/non-product taxonomies), EN/DE assignment, same-language conflict/no partial batch, other-language/per-term preservation, idempotence, drift, write/readback refusal, exact absent/empty/multi-value/slash rollback, rollback failure keeping the existing backup, and connection to `Templates` and the CLI backup/restore path. Product archive HTML bytes remain untouched. Native matcher/Polylang request resolution, actual empty filtering and browser presentation remain parent-owned pending gates, even with unit tests green.
