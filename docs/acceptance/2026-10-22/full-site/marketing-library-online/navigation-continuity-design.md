## Three narrow changes

1. **Respect native navigation before enhancement and on history traversal.** Resolve the current hash to an actual element inside this Library, then use its nearest `data-library-panel` as the selected tab; a valid in-Library anchor takes precedence over the query parameter because it names the native navigation target. Unknown/outside hashes fall back to the existing `tab=documents` rule. Select that panel before hiding the other panel or attempting sticky-offset scrolling. Reconcile `hashchange` and `popstate` without writing history, clearing the search field/type state, or moving keyboard focus. A hash into a panel must not attempt to scroll that panel while search has intentionally hidden both source panels; its tab still selects the corresponding search half. Existing enhanced tab clicks keep their replaceState semantics and drop an obsolete hash as before.
2. **Measure only visible active-panel spy targets.** The scroll spy must ignore hidden ancestors and targets without a rendered box. Only targets in the selected, visible panel may win; the zero rect of a hidden later panel cannot overwrite the visible brand. Clear stale active/aria-current markers when search hides all source panels. Preserve the existing brand/zone links and selection rule; do not derive identity from ID prefixes or fabricate positions.
3. **Keep the reader reachable after a real content transition.** After either a normal-list or search-result tab render, locate the new active panel/result host using its non-sticky content box. On an explicit changed tab, reveal that content's start only if it lies above the measured sticky stack or below the viewport. The old sticky tabbar rectangle is not an anchor: once pinned, its rectangle plus scrollY minus header height merely reproduces the current scrollY and cannot move a stranded reader. For query changes, correct the viewport only if the newly rendered result host is wholly above the measured sticky stack (the footer/stranded-results failure). Do not scroll merely because the reader is somewhere inside a long valid result list, because the result starts below the viewport while typing at the page hero, or on every keystroke. Keep focus on the customer's input/tab; use existing measured header/tab/chip offsets and reduced-motion behavior. No fixed header height, forced top-of-page jump or autofocus is introduced.
