# Native interactive design evidence

The parent used the actual p548 WordPress page with Computer Use, its real private
project gateway and real Three/R3F renderer. These are synthetic test inputs. No
account credentials, cookie, authentication context or external project are kept.

`manifest.json` fixes every retained artifact by SHA-256, byte count and capture
stage. Captures span iterative native testing; they are not all evidence of a
single fixed source SHA. The `*-current.png` pair was captured after the strict
entry-directory module guard and SVG constraint-order correction, with emitted
scene `SceneViewport-BQc4p_xn.js` and core `planner-core-BPeYb1o3.js`. It booted
revision6 and rendered WebGPU. The native keep-out polygon was directly clicked,
selected in the object tree and exposed its numeric properties without an edit.

The native retry record is from the preceding corrective build. It records the
failed module request and subsequent `planner_retry=1` request, one real WebGPU
canvas and the exact raw invalid rows `2.5` preserved through failure/recovery.
`retry-fixed-before.png` and `retry-fixed-after.png` show that transition. The
synthetic form was then cancelled explicitly, leaving revision6 unchanged.

`native-saved-revision{2,6}.json` are real project readbacks. The geometry checker
response is `native-review-revision6.json`, not a copied UI result. Native pointer
moves are recorded in `plan-drag-values.json` and `three-drag-values.json`; the
screenshots cover cancellation, pitch limits, German invalid decimals and both
languages at1440/390. Earlier camera frames are progression evidence, not a final
app-layout signoff. Missing touch dispatch, actual device-loss and maximum-size
phone performance remain unproven; see ../DESIGN-REVIEW.md.
