## Defects opened

- **#481** H2 T3 × B2-5.0-HV1 is answered `released_with_accessory`, while its own cited condition says the one-module battery runs at 89.6–115.2 V, below the H2 T3's 180–800 V window. The engine fixture test expects `not_released`, but it reads `services/engine/tests/fixtures/compatibility.json`, not the shipping file. The two data files have diverged beyond this pair (248 pairs / 7 requirements against 251 / 10; H2 × B2-10.0 is `released_with_accessory` in shipping and `released` in the fixture; the fixture carries two `backup` requirements and three `parallel_controller` requirements, shipping has none and one). The H2 path therefore proposes B2-5.0-HV1.
- **#482** H2-10K-T3 gets a DTSU666 meter line while its inverter line says the box contains a smart meter, three CTs and a 10 m cable. The shipping contract holds both an `included` and a `not included` meter requirement for the family and `_requirement_lines` only filters the latter, so the included record cannot suppress the line.
- **#483** `backup=needed` and `needed_accessory_ok` return `no_candidate` for every home request. The reserve is sized correctly (C17), but the backup eligibility gate needs a cited `backup_power_va`/`backup_power_kw` which the engineering feed drops for home inverters (the feed only carries figures with a hosted citation, `plugins/linker-commerce/includes/Products/EngineeringFeed.php`), and the shipping compatibility contract has no backup requirement. The fixture has two backup requirements, and no unit test exercises `needed_accessory_ok`.

## Notes and limits

- The C17 no-candidate screen does not render the engine's report, but the response does; the report's storage section is quoted above. The design report screenshots exist for the runs with a selected system.
- C56's stricter-of-two branch is not reachable through the UI with the published products: `probe.json` enumerates the 59 inverters × 25 published batteries and finds no pair with two matching entries of different verdicts. The engine's `pair()` on the shipping contract answers `not_released` for EF HD-P1-10K0-S2 × EF BD-5.1-S1, which is real contract data but a draft battery.
- C54's phase filter is not independently observable: the not-included meter requirements carry phase 3, and the phase rule already excludes a 1-phase request from those 3-phase inverters. A current-transformer-only requirement would be invisible because the code has no CT kind; the shipping contract has no such requirement and the GW80K included condition names CTs as separate items.
- `dc_ac_ratio` and `pv_input` are algebraically the same constraint when the cap is the manufacturer's max PV input over AC: `kWp / AC ≤ maxPV / AC` is `kWp ≤ maxPV`. Both are reported with their value and limit, as spec 14 line 18 lists them; the second never excludes an inverter the first does not.
- The report screenshots are element crops of the sections at the named viewport widths (the content column is 887 px wide at 1440), not full 1440 px frames; the whole report crop contains every section.
- No Test Mail, inquiry, registration, draft write or save happened. `record.json` lists every non-GET browser request; all of them are the `design/residential` call the form and the swap make.
