## Final native boundary

Woo `WC_Data::save()` dispatches `woocommerce_after_product_object_save` after its data store's update/create. The editor, Woo REST and Woo CRUD converge there. Woo owns products, fields and durable Action Scheduler jobs; it does not supply the site's generated fact/document/SHA binding. LC has no evidence-maintenance role. The custom seam only initializes missing evidence at this native event.

`Module::product_saved()` first calls `EvidenceBindings::capture_missing()`, then emits the existing preparation signal. Capture refreshes the saved locale and canonical publication read, then uses the existing per-entry adoption. `array_key_exists()` preserves every already recorded entry exactly, including null, scalar, malformed-array and stale-SHA entries. Only a missing entry can bind to its current explicit hosted source. An existing non-array whole container is retained fail closed. A normal whole-map `[]` may receive its first entries. No state table, special publication policy or second manually maintained source is added.

Complete maps need no PDF reads during adoption. Only the document assembly is skipped: the normal generated next map still drops deleted/invalid raw rows. Explicit changed-fact capture keeps its existing behavior; unchanged/stale recorded entries never acquire new bytes through routine publishing. Draft status, explicit document withdrawal and missing relations independently block facts, FAQs and original-URL access.

Plain status-only `wp post update` changes current publication permission and queues preparation through WordPress hooks. It is not a completed Woo object save and does not initialize missing bindings. Product/technical-source maintenance uses the Woo editor, Woo REST or Woo CRUD. No delayed CLI-specific adoption mechanism or per-tool manual synchronization is introduced.
