## Implemented authority and recovery data

A real frozen run must already pin the exact plan under
`weather_acquisition.plan`. Its active lease may create a durable intent and
atomically consume its one POST permit. An unconsumed permit can resume after
interruption. A consumed permit with no verified reply remains unknown; neither
lease replacement nor stale caller flags create another permit. The original
deadline persists and is checked before authorization.

First acknowledgement, provider/storage identity, latest progress, terminal
observations and abort replies are retained privately. A late reply may record
an actual external effect after cancellation or lease loss. It cannot change
the task state, issue another permit or publish an owned project asset. Late
nonterminal observations cannot erase a terminal fact. A recorded abort reply
is distinct from an observed terminal `ABORTED` status.

The existing strict original-TMY parser validates a complete source before
retention. Source request/interpretation must match the frozen plan and the
source must name the acknowledged succeeded run. The original bytes, capture,
plan, provider facts and evidence children are hash-verified and immutable.
Exact retries reuse the capture; conflicting replacement is rejected.

An owned journal projection follows project ownership, including guest/account
transfer, with the established not-found response for other principals. New
journal references are included in whole-workspace archive validation. The
additive table is optional when verifying an older core-v2 archive and is
created during private restore; no live schema migration occurred here.
