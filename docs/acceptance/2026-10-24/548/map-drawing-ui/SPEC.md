# Persistent manual roof drawing in the unified workspace

2026-10-24, continuation of the active [unified workbench rebuild](https://github.com/AssassinFlash/de-linker/issues/548). This increment mounts **new manual roof-face creation** in the existing Journal map view. It does not close the whole goal, add provider measurements, or claim country, equipment, electrical, structural or production approval. The earlier [drawing domain/controller contract](../map-drawing/SPEC.md) remains applicable; source/plane/ownership and common project history are required here.

## Required behavior

- The existing map/plan/3D views remain views over one metric project geometry. Map drawing requires the existing recorded geographic origin and true-north reference; missing references leave the existing coordinate editor available. All existing site styling remains on the same WindPress pipeline and tokens. No dependency or global React upgrade.
- New drawing starts empty. Each accepted physical primary completed tap/click appends one quantized geographic point. Pan, multiple pointers, cancellation, secondary buttons, double-click duplicate releases and late events do not add points. Keyboard users can pan the normal map and activate Add corner at map centre. These display handles do not declare survey precision.
- An application-owned open prefix renders points and an open line for two or more points. Reload/pause/reopen can retain 1, 2 or 3+ points and continue with real new input. Nothing infers closure or imports private SDK state. Finish explicitly stages a closed ring with at least three unique valid points; only then does the pinned Terra Select adapter own vertex/midpoint/delete interactions.
- Before application, a named roof face needs explicit pitch, down-slope true-north bearing, relative height, source note, rights basis, calibration/measurement conditions and a retention/derivation declaration. Precision can be unknown and export permission stays independent. Values start empty, including flat/zero values. Raw invalid numeric strings and their original locale remain recoverable. The height position is frozen at the first recorded geographic point and visibly marked; reordering/deleting a boundary corner cannot silently move the roof plane.
- Source/plane confirmation and accepted geographic-to-ENU-to-roof projection produce one group-before command adding one source and one roof, with stable domain IDs derived from the drawing key. Existing roofs, holes, arrays and source facts remain unchanged. One common undo/redo step must reverse/reapply the result without losing other project inputs.
- Proposed geometry is checked through the current native-owned `geometry/review` route before application. A new roof's invalid polygon/numerical diagnostic, incomplete review or truncated diagnostics prevents application while retaining the drawing. Source declarations and a successful geometry check do not establish measurement accuracy or engineering approval. Inputs and source declarations are sent to the project's existing engine route for this check.
- Drawing is isolated from other editor mutations while active. Pause flushes local recovery before allowing navigation or project save. Provider replacement/renderer failure can release only the renderer and retain the buffer. Drawing adapters must stop before map removal. Construction or cleanup failure must not prevent the map owner from releasing its map.
- Browser recovery is a separate untrusted versioned journal, bounded to 8 MiB per drawing and 32 records/32 MiB per verified scope, with the same aggregate list bounds across admitted scopes. These are local resource limits, not engineering quantities. No silent eviction. Only current native grants and the currently opened project admit records. Delayed former-scope callbacks must not write or expose data under the new identity.
- Mutable journal updates and deletion use exact compare-and-swap. An older tab cannot overwrite/delete a different saved version. Unknown write acknowledgement is retryable with exact bytes. An explicit separate copy preserves both competing drawings. Initial list failure and write/retirement failure have accurate messages and usable retry actions.
- Before committing, the exact proposed result is itself journaled. It remains protected after the React project command, after closing its preview and before a confirmed server save. Only an exact native-confirmed geometry retires that prepared journal automatically; a forged prepared payload must not authorize cleanup. A stale baseline remains available but cannot silently rebase onto changed geometry.
- English wording and independently composed formal German ship together, with recorded adversarial review. The customer sees an application workflow, without synthetic SDK controls, debug JSON or internal transport details.
- Repeatedly opening a cached lazy viewport must resolve normally. Keep module-export identity and explicit retry URLs; each new React lazy payload receives a fresh thenable. Apply the same correction to the 3D loader because it shares the affected pattern.

Existing-ring, hole, obstacle and keep-out drawing UI remains part of the active full goal, alongside provider imagery/3D coverage, final calculation/equipment/report consumers and site migration/review/prod/readback.
