# Existing boundary editing in the unified map workspace

Continuation of the active unified workbench and whole-site goal. Base source
`252a022e41f8ca5426d6463206c8346eb89da5f1`. The accepted drawing controller and
manual-roof contracts remain applicable. This increment mounts existing roof
boundaries, individual roof openings, obstacle footprints and keep-out footprints;
new region creation and the remaining whole-goal consumers remain required work.

- Select an existing roof, obstacle or keep-out in the same design-object list
  or map. For a roof, choose its outside boundary or a particular opening. A
  hole's index is scoped to the frozen whole geometry and is never a permanent ID.
- Reuse the pinned Terra/MapLibre controller and accepted metric ring operations.
  One completed pointer transaction updates the working ring; the project is
  changed only by explicit Check and apply. Original metric values for untouched
  vertices, plane, other holes, extrusion, source records and unrelated objects
  remain exact. A quantised display collision leaves numeric editing available.
- Both new-roof and existing-ring working data use one scoped journal and writer.
  Existing v1 roof records remain readable without rewriting or widening their
  CAS. A discriminated v2 ring record carries the frozen target, current metric
  and geographic pairs and an explicit source-review declaration. Decode checks
  pair correspondence against original points or the accepted geographic-to-roof
  operation; it cannot trust an independently supplied metric ring.
- Keep the existing native identity grants, bounded storage, exact uncertain-write
  retry, stale-tab deletion protection, explicit separate-copy action and original
  locale. Reload, pause, renderer replacement and interrupted edits retain working
  data. A separate copy is a new journal identity for the same domain operation,
  not a new edited-object identity.
- The recorded roof plane and original source statements remain unchanged.
  The interface shows the source/declared precision and requires confirmation
  that the source and permissions cover this edit. This is a user declaration,
  not newly verified accuracy. It cannot silently promote export permission or
  replace a licensed source with an unrestricted manual source.
- Check the proposed document through the current owned geometry-review route.
  Incomplete/truncated/numerically unsupported reviews or an invalid edited
  polygon refuse application and retain the edit. Other layout conflicts remain
  visible through the ordinary layout review. Parse/coordinate success alone is
  not topology, measurement or engineering approval.
- Prepare the exact result in the journal before one grouped project command.
  Common undo/redo, 2D/3D, quantities and Save project consume that same document.
  An unchanged boundary creates no project history step. Only exact server
  confirmation retires prepared working data; a stale whole frame cannot rebase
  or overwrite another edit. Result visibility and truthful status after undo
  also apply to repeated unchanged resubmission.
- Keep the A/Journal layout and WindPress/token pipeline. EN and independently
  composed formal DE receive adversarial review. Actual EN/DE at 1440/390 must
  verify selection, edit/correction/refusal, source declaration, reload, shared
  history/views and native save/readback; fixture results are identified separately
  from GPU/provider/touch evidence. Full goal acceptance remains open.
