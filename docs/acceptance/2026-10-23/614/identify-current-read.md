# Current identity read without technical document hashing

The root integration owner observed that the knowledge build may identify each text passage separately. The previous `identify` dispatch first assembled the full publication manifest, resolving and hashing every allowed PDF before returning only the caller's model status. The observed full read was approximately three seconds on the snapshot with roughly 600 MB of hosted PDFs; this note does not claim a measured HTTP improvement before the root reruns it.

`Publication::model_statuses()` is a narrow current projection from the same native Woo source. Each call refreshes only request-local object-cache copies once, uses an uncached native product query across the existing statuses/languages, reads native `pa_model` term names, and applies the existing canonical+locale publication rule plus the reference-role restriction. It does not assemble product facts, parse figures/FAQs, resolve uploads, hash PDF bytes, consult preparation state or maintain a cross-request model cache. Existing `is_published()` semantics are unchanged.

The public controller still returns only model labels already supplied in the client's label list or bounded input text. Unknown labels remain unknown; withdrawn/source-blocked/locale-draft/reference labels return unavailable without an ID or facts. Duplicate labels retain the existing preference for a currently published ordinary product. Unavailable request-local refresh and failed native term reads return explicit 503. Responses retain no-store/private headers. There is no TTL or shared Redis flush.

The committed `IdentityTest` supplies a real hosted PDF association and makes every upload-directory read fail, so the old path reproducibly failed in `DocumentFiles::resolve`. The new identity path passes without entering that resolver, refreshes once per request, and covers subsequent draft/role changes, canonical and locale publication, duplicate model labels and native-read errors.

Verification: the targeted identity suite passed **5 tests / 41 assertions**; full Commerce unit passed **1,290 tests / 6,618 assertions**. Full level-8 PHPStan and WPCS for all four changed PHP files passed. The modified HTTP runner passed Python syntax parsing. Real shared-Redis/two-process HTTP execution and latency measurements remain explicitly pending with the root integration owner.

The existing local-only HTTP race fixture now supports `identify-hold`. It calls the actual public text-identification route, primes the reader process's native caches, waits while a separate HTTP worker changes the fixture product to draft, then calls the route again inside that same reader request. The companion `publication-http.py` asserts published→unavailable, distinct worker PIDs, no public product ID after withdrawal, and zero entries into the real document resolver. It restores only its existing fixture products in the established cleanup path. No new instance or MU loader was created by this worker. Root owns the shared runtime and runs this fixture and actual endpoint timing after merging; this worker has not run its writes.
