# 正确方法的独立研究：统一光伏、负荷、储能与系统选型合同

2026-10-22。研究责任：Codex。范围是新的领域与计算架构，不是给现有引擎补丁；本目录不导入或修改业务引擎，不用旧输入模型限定新方案。

## 1. 本轮回答什么，证据怎样分层

本研究回答：哪些公开方法能够支撑欧洲住宅与工商业的同一光储计算内核；计算究竟应吃什么数据、保持哪些物理约束、产生什么结果；怎样证明可行性，怎样避免把能量、功率、备电、控制目标和设备放行混成一个推荐分数。

结论是：**住宅与工商业可以共用母线能流、设备能力、连续状态与验证机制；两者区别在负荷、计量、控制任务、设备与适用条件。屋顶/发电模型、设备电气模型和调度策略应通过明确合同组合。** 已建立独立于业务代码的AC耦合参考计算，并执行17组手算边界、数学求解与独立账本核对。它证明部分方法在明示模型中的可行或不可行，不证明任一SKU、任一实际现场或整套新产品已通过工程验收。

证据等级必须分开：

- **官方原文**：OpenSolar储能方法，SMA multiuse与负荷导入，当前SAM BTM/FOM、Battery Cell/System与Grid Outage，PySAM Battery/BatteryStateful接口。正文、运行ID和hash在本目录raw中。
- **守恒推导**：根据明示AC/DC边界建立公式并核单位，标为本研究推导，不伪称逐字摘自某标准。
- **自写参考与解析核对**：`reference.py`的MILP存在性求解、另一套标量能量/来源账本，以及人工可算界限。即使三者一致，也不等于运行过SAM或通过现场校准。
- **官方模型实际执行**：隔离安装官方文档指定的`nlr-pysam==8.0.0`，运行BatteryStateful的4项物理模块检查。它与手算电荷/功率关系核对，但未完成该官方模块与自写MILP的全功能等价验证。
- **尚待设备与工程验证**：具体端口、电压/电流、降额、固件、并网/离网/切换及国家依据，气象与现场精度，真实控制器表现和预测误差。本研究不将这些未知填成默认通过。

## 2. 原始方法支持了什么，也没有支持什么

| 原始来源 | 本轮读到的实际方法 | 对新内核的约束 | 不能据此推出 |
|---|---|---|---|
| [OpenSolar储能方法](https://support.opensolar.com/hc/en-us/articles/12382460685455-How-OpenSolar-Models-Battery-Energy-Storage) | 全年逐小时、可用容量、充放电功率、损失、衰减、控制及可覆盖负荷；分AC/DC耦合 | 容量与功率、负荷可覆盖部分、控制策略均须参与；不能只以年耗配电池 | 小时模拟等同15分钟削峰精度；所选设备真能执行该策略 |
| [SMA multiuse](https://manuals.sma.de/SDesign/en-US/14444632075.html) | 用同一电池SOC区间协调自用和削峰，允许条件化电网补能 | 多目标应共享状态，并定义优先级、保留区和补能规则 | 分别求容量再相加；任意SOC阈值都最优 |
| [SMA负荷导入](https://manuals.sma.de/SDesign/en-US/14318222475.html) | 指定起点、完整周/年、间隔、单位；整周会外推年 | 采样率、时间边界、单位和外推语义是一等输入 | 一周绝对不能用；把条数直接当成15分钟时序 |
| [SAM BTM储能](https://samrepo.nlr.gov/help/battery_storage_btm.html) | 住宅与商业共用BTM；名义容量/有效容量、串并数、分向变换、电压、热和损失；提醒自动定容可能产生不实际的数值 | 区分设备构型、能量表示与运行模型；适配后要读回实际配置 | 通用电芯自动定容结果就是可采购SKU；已有手册URL足以校验构型 |
| [SAM BTM调度](https://samrepo.nlr.gov/help/battery_dispatch_btm.html) | SOC限值与初始SOC，充/放电保持时间，削峰、自用、功率时序目标等，限定充电来源 | 可替换策略与可执行控制约束独立于物理状态；初始状态显式 | “理想调度存在”表示现有EMS可以实现 |
| [SAM停电模型](https://samrepo.nlr.gov/help/grid_outage.html) | 关键负荷与停电时序；停电时无电网收发；正常与停电SOC下限分开；可从每一时刻评估停电续航 | 备电是带初始状态与场景的任务，不能仅加一项kWh | 所有停电都始于满电；能量足够就有离网/切换能力 |
| [PySAM BatteryStateful](https://nrel-pysam.readthedocs.io/en/main/modules/BatteryStateful.html) | 单时间步物理模块，含电压/热/容量/寿命，不含削峰等调度 | 可用作替换物理适配层及独立模型核对的候选 | 它已验证站点全部调度、端口拓扑和供应商设备 |

更深的适用限制来自SAM自己：其DC耦合建模会把指定逆变器当成可双向的混合机，即使实际型号不支持；REopt传回的调度使用不同系统/天气表示，当前SAM集成有小时步长及子阵列限制。因此，**外部成熟引擎也不能替代设备适用性与接口一致性验证**。可以复用方法或模型，但不能直接把“它返回结果”当作产品选型放行。

本轮也对官方网页做了量纲检查：SAM帮助页把电芯Ah×V×电芯数标为kWh，展示式缺Wh→kWh的1/1000；其“AC最大充电功率”等换算文字也应按实际功率方向核对。这是网页展示式疑点，不能据此宣称SAM程序同样错误。后续适配必须用实际库输出与独立单位核对，而不是逐字复制网页公式。

官方抓取的当前SAM域名为`samrepo.nlr.gov`、`sam.nlr.gov`。旧`samrepo.nrelcloud.org`请求未取得正文，失败记录保留；没有将搜索摘要或失败页面当成方法证据。Apify最初HTTP402经同组核查为并发内存限制，低内存单次运行后继续取证，未更改账户预算或绕过Apify。

## 3. 统一的领域数据，而非住宅/商业两套算法

建议纯领域内核只处理已规范化的数学与事实对象；数据库、HTTP、天气下载和Woo商品读取留在适配层。

| 对象 | 必须携带的内容 | 进入内核前的要求 |
|---|---|---|
| TimeAxis | UTC区间起点、每段真实持续小时、原时区、时间戳的起/末/瞬时语义、缺失与重采样记录 | 时间有序、无重复，能量积分可复核；DST、闰年不由数组长度猜测 |
| ProjectTopology | PV阵列、DC/DC、PCS、AC母线、电网、负荷/关键负荷、计量点与开关的有向端口图 | 新建/既有、净购电/总负荷语义明确；不能重复扣除已有PV |
| ArrayYieldSeries | 每阵列实际片数/姿态、可用功率与实际出力、温度、模型/天气版本及粒度 | 布局到发电数量一致；削顶、遮挡及限发在正确位置发生 |
| StorageState | 电量或电荷表示、容量基准、物理SOC窗口、退化状态、温度、来源账本、初始状态 | 名义/可用容量不重复扣DOD；初始未知来源不算太阳能 |
| CapabilityEnvelope | 逐端口、逐运行模式，电压/电流/连续和峰值功率、持续时间、SOC/温度/寿命条件、附件/固件/控制器 | 值有原文、版本、页码及适用条件；unknown不填铭牌默认值 |
| OperationPolicy | 可观察/预测输入、控制目标优先级、SOC保留、可充来源、滞回/最短保持、控制周期、可用EMS命令 | 完美预知、滚动预测与实时策略是不同模型，不混称可执行 |
| TaskSpec | 自用、指定计量窗削峰、关键负荷停电、既有机改造等；硬目标与比较偏好分别列出 | 必须明示任务和适用域后才可说“可行” |

设备条件化能力不能简化为几个铭牌取min。应计算/引用在当前状态、端口、相与模式下的能力函数；只在明确串联功率路径、对应同一工作点且各限制均已验证时，取min才是必要上界，并且仍不自动成为可保证输出。并网配对放行也不能跨成离网或切换放行；并联上限可以随网络拓扑、控制器/STS、地区与工作模式不同。证据不足时返回具体缺项。

## 4. 公式台账：边界、来源、适用域与数据依赖

以下是AC耦合最小模型的明确约定：`L_t`是总AC负荷，`S_t`是PV逆变器后可用AC出力；`C_t/D_t`分别是AC母线流入储能/储能流到母线的非负功率；`E_t`是物理可用SOC窗口内的内部储能kWh。固定效率只用于本轮可解研究例，真实模型须适配实测/厂商条件。

| 式/约束 | 明确含义和来源归属 | 适用域与数据依赖 |
|---|---|---|
| `energy = Σ power_kW × duration_h` | 单位定义与能量积分，本研究推导；SMA的功率/能量及间隔合同支持该输入区别 | 值须为区间平均功率；瞬时气象输出不能无声明伪装成平均测量 |
| `S + G_import + D = L + C + G_export + curtail + Aux_AC` | AC母线守恒，本研究根据端口边界推导；与SAM/OpenSolar分转换路径一致 | 仅同一AC母线；DC耦合必须增加DC节点、转换和共享逆变器约束 |
| `E_next = E + η_c C Δt − D Δt/η_d − Aux_internal` | 内部状态守恒，本研究推导，不是冒称SAM逐字方程 | 两方向效率及辅助损失位置要定义；AC辅助负荷不能再次全量扣内部能量 |
| `0≤E≤C_available`；正常`E≥reserve` | 有效窗口容量与任务保留；SAM SOC限值/初态，SMA SOC分区 | 若已用usable容量，此处不再乘同一DOD；退化/热引起的可用容量变化须另有模型 |
| `0≤C≤P_charge_cap(t,state,mode)`；`0≤D≤P_discharge_cap(...)` | SAM/OpenSolar分功率限制；本研究约束表达 | 连续/峰值、相、端口V/I、温度/SOC、固件与EMS均可能限制；不能直接拿PV逆变器AC铭牌作电池输出 |
| `C×D=0`或明确允许的多储能拓扑 | 本轮单一储能的互斥约束；MILP用二元状态实现 | 多柜可一充一放时不能无条件套同一个全站互斥，但每个物理设备仍有模式 |
| `G_import≤target(t)` | SAM输入电网功率目标的对应表达；目标发生在已定义的计量点 | 瞬时限值、15分钟需量平均和计费窗口不是同一约束；需据当地计量定义 |
| `E_end≥E_start`或显式一次性库存消耗 | 防止免费初态能量，本研究用于可重复运行的边界条件 | 季节跨期/停电一次性任务可另定；不得将循环中耗尽初态说成年复一年可持续 |
| `AC_recharge ≥ AC_discharge/(η_cη_d)` | 当初末内部电量相同且忽略其他损耗，由上式独立推导 | 只可用同一边界的效率；真实热/内耗等只会增加需求，不能把94%当所有SKU常数 |
| `solar_autarky = (PV_direct_load + battery_PV_origin_load)/gross_load` | 采用负荷得到的太阳能为自给率；HTW定义与来源账本的明确延伸 | grid充入与初始未知能量不能计PV；如需“所有本地能源自给”应另命名 |
| `PV_onsite_input_share=(PV_direct_load+PV_charge_AC)/PV_available_AC` | 本轮对“可用产量”的现场使用份额，名称注明边界；不是有弃光时的标准自用率 | 本例无储能外送；期末PV库存、损耗、弃光口径须披露；不能与“PV实际给负荷比例”互换 |
| `PV_self_consumption=(PV_direct_load+PV_charge_AC)/(PV_available_AC−curtail)` | 当curtail表示未实际生成的出力、且无电池外送时，按实际发出电量定义输入侧自用率；与[HTW定义](https://solar.htw-berlin.de/faq-unabhaengigkeitsrechner/)中计入电池充电的口径对应 | 必须区分可用潜力、实际发出、直接外送、储能外送与库存；所有电量在同一AC边界。无实际发电时为未定义，不填0或100% |
| `solar_autarky≤PV_energy/gross_load` | 初始PV库存为0的无损上界，能量守恒推导 | 有已确认初始PV库存时需加库存；用于不变量，不是预测公式 |
| `P_DC_kW = V×I/1000`；`C_nominal_kWh=V_nom×Ah×cell_count/1000` | 电气量纲关系；SAM单元/串并电压电流模型提供结构 | 电压随SOC/T变，串并和DC/DC拓扑须明确；名义能量不是全过程可交付能量 |

**效率来源要保留性质。** OpenSolar明示使用`η_single=sqrt(η_roundtrip)`作为对称化模型；它能复现指定回路效率，却不能推出设备两方向真实效率相等。若只有回路效率，允许在初筛中使用这一已声明假设，但精确功率与备电候选不能伪装成已有分向实测。SAM把电压、热和容量等进一步建模，也仍需真实参数。

**电网充电归属要有账本。** 本轮维护PV、grid、initial_unknown三种内部能量份额，充入分别乘充电效率，放电按当前混合比例分配出力与损耗。比例混合是本研究的透明记账约定，不声称电池里可区分电子；其他FIFO等方法可替换，但必须同样闭合，且不能把grid充电计入太阳能贡献。

自用率的实际发电分母不能与可用潜力混用，储能损耗也不能同时算成给负荷的太阳能。参考输出因此分别给实际发电自用率、可用产量现场使用份额、实际太阳能供负荷比例。HTW原始定义的当天Apify快照已在[前一阶段证据](../raw/06-faq-zum-unabh-ngig-keitsrechner-htw-berlin.md)保存，本研究只复用定义，没有复用其住宅数值表作为新预测方法。

## 5. 已执行的独立参考计算

`reference.py`不import Linker代码。SciPy/HiGHS MILP求在明示固定效率、容量与功率下是否存在满足任务的调度；源/去向流量分别建变量，包含单储能充放互斥、SOC、初末边界与grid限制。可行解另由标量账本逐步复放，检查功率、母线、内部能量、来源、SOC和终态。解析界限不用求解器结果当答案。

本轮目标函数是在给定峰值硬约束内减少总grid电量，附极小吞吐打平项；它不是经济优化、不是全局最优选型，也不证明该调度能被设备EMS实时实现。求解器中断与数学不可行分开；数值容差1e-7只属这些无噪声合成算例的检查，不是现场精度承诺。

| 算例 | 事先可核算的预期 | 实际结果 |
|---|---|---|
| 连续20kW负荷20:00–04:00，目标10kW | 需交付80kWh；η_d=.94时至少85.106kWh内部能量 | 42.6kWh不可行；85.106可行，并在外部低负荷时恢复初态 |
| 1h超峰10kWh、1h补能，初末相同 | 两向.94时需11.317kWh AC补能 | 10kWh余量不可行；11.317足够 |
| 两阶段PV2.208kWh、负荷4kWh，无初始PV | 无损自给上界55.2% | 无损参考模型达到55.2%，没有超界；它是缩放能量例，不是真实年气象 |
| 停电10kW×1h，电池20kWh | 仅5kW出力仍不能供负荷 | 5kW不可行；10kW可行 |
| 强制先grid充5kWh后放5kWh，无PV | 太阳能自给率必须0 | 求解与独立源账本均为0；人工时序账本也通过 |
| 初态5kWh、停电负荷5kWh，无输入 | 可一次性供电，但无法同时恢复5kWh终态 | 自由终态可行；终态≥初态不可行，且初态不计太阳能 |
| PV充放电两向.9 | 输入侧自用率与实际PV供负荷比例不同 | 两项分开输出，损耗闭合 |
| 10kWh中保留4kWh备电，负荷8kWh | 正常调度最多动用6kWh | grid至少补2kWh |
| 先由PV存入6kWh，两段负荷3/8kWh，grid上限4kW | 留4kWh削峰，前段仅放电2kWh；后段4kWh削峰 | 人工SOC分区时序与MILP均可行；普通贪心先用3后仅余3会到5kW购电峰值；来源账本确认这6kWh来自PV |
| 上述任务另保留4kWh备电 | 同一库存不能同时花作备电及削峰 | 初态6不可行；初态8可行 |

输出在[reference-results.json](reference-results.json)，共17条运行记录，包括对照条件。本研究的手工multiuse时序展示SOC分区结构，不是复制了完整SMA控制器；阈值4kWh仅为例子，不能作为默认推荐。

该最小AC模型暂不包含电化学/热、衰减、辅助耗电、储能外送、多相不平衡、多柜独立运行、DC耦合与共享混合逆变器。它是用于新内核的解析验收参考；这些能力仍属于目标，需要对应适配与基准，不能以此参考模型缺省为理由从产品删掉。

### 官方物理模块对照：已执行的4项检查

按[官方安装页](https://nrel-pysam.readthedocs.io/en/main/installation.html)将`nlr-pysam==8.0.0`仅安装到本目录被git忽略的`.runtime`，没有修改项目或全局依赖。执行[official_crosscheck.py](official_crosscheck.py)，固定LFPGraphite参考配置及显式初始/最小/最大SOC，不代表任何供应商SKU。

| 官方模块检查 | 事先独立关系 | 实际输出 |
|---|---|---|
| 1A、0.25h单步 | `Q_after=Q_before−I_actual×Δt`；`P=V_actual×I_actual/1000` | 两个残差均0 |
| 0.01A、100步共25h | `Q_end=Q_start−ΣI_actualΔt`，跨日不恢复库存 | 电荷残差4.97e-14Ah，时间索引连续超过96 |
| 电池端DC功率命令1000kW | 实际输出受物理模型状态限制，不等于命令 | 电池端实际14.86350046kW DC，SOC15.00008486%，与显式15%下限相容；未计PCS的AC输出 |
| 参数与状态读回 | 名义kWh/V输入，与实时Q/Q_max、温度和SOC含义分开 | 保存完整输入侧参数及有效状态；不能据名义容量×SOC直接承诺交付 |

输出在[official-crosscheck-results.json](official-crosscheck-results.json)，含软件版本、平台和模块二进制hash。零电流初始化步骤用于得到实际状态；`setup()`后的Q/V占位输出没有被当作真实初态。该步骤还暴露：默认配置不替用户填初始SOC，适配器必须显式提供。

这些检查提供了真正外部实现的物理关系对照，但**没有运行SAM Battery整年调度，没有验证自写MILP所有流量、效率与归属都等同SSC，也没有验证实际LFP产品或现场**。参考模型目前是固定效率能量状态，BatteryStateful是电荷/电压/热/容量状态；两者须通过明确转换合同再做相同场景的系统级对照，不能把一个P=VI检查说成全模型通过。本轮GitHub源码页面只取得文件元信息，未读取完整SSC C++，不声称完成源代码审查。

## 6. 备电、多目标与选型的正确合同

**备电场景**必须确定停电区间/假想开始时刻、关键负荷、PV孤岛时是否可用、grid=0、该模式的能力/最小SOC及切换/启动附件。应从正常调度得到停电初态，或明确说明测试了一个指定初态；不能所有时刻默认满电。备电续航可以按开始时刻给范围或失败见证，而不能用单个P×h就承诺整年任意时刻同样续航。SAM的停电SOC放宽是其策略假设，真实设备能否如此要单独核实。

**多目标**分硬条件和偏好，例如先保证某计量窗峰值不超过目标并持有备电，再在余量内提高太阳能供负荷。各目标对同一状态约束，策略要清楚表达。SMA的SOC分区是成熟路线之一，不是唯一最优方案；完美预测求解可以给物理可达上界，滚动预测/在线规则要另用预测误差和实际控制周期验证。

**候选生成**应先枚举有依据的具体设备配置图：实际组串与MPPT、可用电池模块/柜、模式化兼容、附件、控制器与并联；每一个数量变化都重建图及能力约束。组件数不能在字符串层隐式增加。资料不齐的组合可保留为待核，但不进入“已验证可行”集合。

**评估与排序**应先对同一项目时序、任务和场景检查可行性，再比较任务指标。可以列Pareto候选或按明示优先级排序：任务完成程度、最坏时段余量、PV实际供负荷、grid峰值、能量吞吐、所需设备/附件等。只有已定义目标才谈最佳；设备ID仅可打平稳定顺序。HTW容量上限、无损能量下限可用于解释或剪枝，不直接当最终容量目标。不采用回本期或凭空的费用优化。

**“存在可行调度”与“实际可实现”是不同结果。** 可行解给出物理见证；还要验证某EMS/固件支持的命令、量测、时限、充电来源、模式切换和控制抖动。若只有理想调度通过，结果标为该模型下可达，不能包装成该SKU已能完成任务。

## 7. 新架构的阶段、结果、异步与不确定性

建议架构是纯领域内核加可替换模型适配层，不指定必须拆微服务。CPU密集运行可由异步worker执行；编排器依赖明确的阶段产物，而不是在HTTP请求中偷偷读取最新数据再拼报告。

```text
ProjectRevision（不可变输入、来源和任务）
  → NormalizeInputs（时间轴/计量/拓扑/证据检查）
  → BuildPVSeries（布局→逐阵列天气与电气模型）
  → GenerateConfigurations（模式化具体设备图）
  → SimulateOrOptimize（控制策略+物理模型）
  → VerifyWitness（独立守恒/约束/设备与来源检查）
  → CompareCandidates（任务指标与适用域）
  → ResultSnapshot（图/能流/BOM/证据/报告共用）
```

模型适配器分别声明`model_id/version`、输入/输出单位和端口、所需时序、支持模式与域、已做的对照及误差范围。一个AC理想模型不能被静默切成DC详细模型；模型变更改变计算身份。PVGIS/天气、pvlib或其他PV物理、电化学/SAM、简化筛选与设备原文解析互不假装是同一层。

一次Run至少记录：项目revision/hash、TaskSpec、输入数据hash、方法/软件版本与配置、设备/规则证据版本、场景/预测假设、阶段依赖与耗时、随机种子（有随机方法时）、结果与验证见证hash。幂等键来自这些身份；外部资料失败可重试阶段，成功产物不被悄悄覆盖。取消/超时保存中间状态；旧输入或新设备版本到来使结果stale，可看历史，不能当新输入的结果保存或交接。

错误与不确定性应是结构化结果：

| 类型 | 例子及行为 |
|---|---|
| InputInvalid | 单位、时间重复、净购电含PV却按总负荷解释；指向字段/样本，不能变0继续 |
| SourceUnavailable | 气象/官方模型取不到；保留已有几何，不改用未经批准模型补数 |
| EvidenceMissing | 缺某模式的并联/备电/端口依据；列缺项，不宣称设备组合通过 |
| MethodDomainExceeded | 小时模型要求输出15分钟削峰保证、或模型不支持此拓扑；停止该结论 |
| Infeasible | 返回失败时段、违反约束与可复算见证/解析下界，和缺证据区别 |
| SolverIncomplete | 超时、数值/求解中断；保留界限和求解状态，不能冒称已证明不可行或最优 |
| ResultStale | 输入、方法、设备或原始事实版本变了；新计算产生新结果身份 |

不确定性至少分开：天气年际变化、测量/几何输入误差、模型结构误差、参数/设备条件未知、预测及控制误差。历史年份min/max不是总误差置信区间；一个参考住宅±5个百分点不能转成欧洲工商业保证。真实样本不足时给证据状态与适用域，不编造统一准确率。部分成果可导出，但必须明示哪些阶段已算、哪些已验证、哪些尚缺证据。

[contract-example.json](contract-example.json)把实际执行的低产量夹具映射为一个可评审的新领域合同示例：真实输入hash、方法hash和幂等身份，计算完成与能量核验通过，同时设备/现场证据阶段仍blocked，未知误差不填数字。它不是生产API或批准过的最终schema，作用是具体展示“算完了”不能自动变成“该项目已验证”。

## 8. 本轮能证明与不能证明

**已得到可执行证据**：连续状态、方向效率与初末边界能排除原有非物理解；来源账本能避免grid充电和初态库存污染太阳能指标；同一储能可承载多目标，但保留区会形成真实冲突；容量足够不意味着功率或备电能力足够。上述均是新领域合同中的不变量，不依赖现有引擎实现。

**已得到原始方法依据**：SMA/OpenSolar/SAM支持分离物理、配置与策略，按时序而非年总量计算储能任务；SAM实际公开了比最小参考模型更细的电压/热/衰减、模式与输入要求，同时也公开了自己的适用限制。

**已执行外部模型的有限对照**：官方BatteryStateful在单步电荷/功率、25h连续状态、功率命令受限与配置/状态读回四项可核查检查中给出一致结果。这不扩大为系统调度、设备或工程验收结论。

**仍未由这些算例证明**：全欧洲数据精度、厂商配置每个工作点的性能、DC/多相拓扑、在线控制与预测误差、多场景排名稳健性、实际工程/审批与全链运行。这些应作为模型适配和发布的独立证据任务，不再由一个`released`或“算完了”状态代替。
