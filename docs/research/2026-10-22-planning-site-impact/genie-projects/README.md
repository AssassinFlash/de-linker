## 1. 必须作为同一次重构交付的结论

不能只替换工具 UI 或计算端点。现在有六条真实耦合：Genie 的入口预填、Genie 的保存方案读取、账户保存与访客认领、报告生成/归档、工程数据编译与同步、WP/服务保护和发布。它们必须接到同一项目 Interface、同一 revision/run 与实际能力发布包。

最严重的现状是：**“保存方案”只留输入和旧商品行；Genie 读取时重新运行当前住宅算法，回答中却继续拿旧商品行。PDF下载生成也会重新计算。** 改一次算法或 feed，客户看到的旧 PDF、账户商品和 Genie 当前回答可能各自对应不同结果。源码证明这些路径存在，不代表已在客户现场复现差异。应通过版本/输入差异夹具把它作为切换阻断条件，而不是上线后再修。

现状也并非完全没有归属机制：私有 `linker_solution` 有 `post_author`，账户列表按作者过滤，下载和 Genie 有归属检查；访客有 Woo session 暂存/登录认领。**这些是保存方案身份与 session 占有关系，尚不是新架构的私有 Project/revision/run。** 迁移需承接它们，而不能凭新设计名称声称已有项目模型。

## 5. 迁移、回退与接口适配

1. **盘点后建幂等映射。** 切换前导出旧solution id/owner/title/date/kind/input/items/report相对路径与文件hash、Woo访客暂存量及缺文件/无效输入计数；本轮未读生产数据，不虚构数量。建立 `legacy_solution_id → project/revision/artifact` 映射及迁移状态，重跑不重复插入，WP身份保持权威。
2. **按证据区分历史内容。** 旧合法输入导入为“待核实/待重算”的legacy revision，保留旧商品与PDF来源；产品卡空设计迁为产品选择/待完善项目，不造布局、负荷或通过结果。历史算法/天气/能力包不可还原时，明记无法精确重放；不能把旧PDF追认为新内核通过。
3. **建立账户和旧引用Adapter。** 旧账户锚点、solution_id、报告下载链接可以解析到原件/导入后的项目；新动作返回project/revision/run/artifact及持久化/归属状态。页面刷新、登录、不同语言、账户文档、Genie恢复会话都要使用此映射；不继续把数字post id当新项目id。
4. **访客转换后再清旧会话。** 迁移和登录claim验原访客占有，幂等提交新owner，返回可核对回执后清理已成功项。网络超时查回执；失败保留可重试，不能先清队列。多标签页和重复登录不能重复项目或抢走别人项目；丢cookie的恢复策略需明确，而不是依邮箱猜owner。
5. **在隔离环境整体启用消费者。** 新工具、Genie、保存/账户、报告、feed编译与ops一起通过下节路径；以整个项目归属新旧合同，不在同项目混新几何/旧选型/下载时重算。旧端点适配器有明确支持范围，无法表达的新数据不得截断后交旧算法。
6. **回退是组合版本恢复。** 发布清单固定WP Adapter/Genie/React/规划API+worker/schema/能力包；先备份数据库和引用资产，采用可回读的扩展式迁移或提供已演练的反迁移。回旧JS或current symlink不回退新库语义；切回时保留新项目只读及产物，不把新数据塞旧shape，也不丢用户编辑。回退到历史软件不能把已知错误结果标为新系统验证通过。
7. **删除与保留另有合同。** 保存、重命名、复制、归档、删除/撤销共享和资产GC要同时定义；保留期限/配额本轮没有授权数字。清理只处理不再被任何保留revision/run/artifact引用的内容；备份恢复和用户删权需一起验证。
