# 工具重构的后半部分：全站影响、同步修复与交付

日期：2026-10-22。用户明确要求：“重做工具对站点其他部分所造成的影响，并修复这层影响”。本文将后半部分列为同一次重构的必要工作。当前阶段完成依赖研究和修复合同，不把尚未实施的新工具或站点修复写成已完成。

## 1. 完整交付范围

前半部分建立一个面向全欧洲、支持住宅和工商业项目的方案设计工作台；后半部分把所有受这次变化影响的站点入口、保存/读取者、商品与询盘链、Genie、报告、语言和发布机制同步改好。**只有新工作台、相关消费者与实际业务路径一起通过，才交付这次重构。**

影响项不能只写成“兼容旧接口”“后续接入”。每项必须给出当前依赖、新合同、修复落点、迁移方式和真实消费者验收。因本次重构造成的失配在同一轮处理，不留到工具上线后再补。

业务继续围绕产品与方案询盘、Proforma和线下处理。普通产品浏览与直接询盘仍有完整可用路径；系统设计按客户需要进入。

## 2. 本轮核实范围与证据性质

本机主工作树仍为`2b2e826768aa640fca386289ef69dad6b0dc3b6b`，独立研究工作树基于此前研究快照。核查期间发现仓库最新合并引用`origin/main`已到 **`340a11a9cc3a33f687ca8092fcd6285cb9dcfc42`**；各研究对相关消费者用`git show`只读复核并锁定引用，保留自己研究分支。

当前静态依赖与此前r549浏览器证据分别标注。仓库合入不等于线上已运行该版本，本轮未把340a声明为生产读回。没有注册、提交真实询盘、发送测试邮件、改产品代码或部署。

本轮独立研究分工为[入口/内容](https://github.com/AssassinFlash/de-linker/blob/f31a2c8ae088fa8a41bec32891c78f1db70187f1/docs/research/2026-10-22-planning-site-impact/entry-content/README.md)、[商务交接](https://github.com/AssassinFlash/de-linker/blob/0488c5af518396878f5044a205cf0745c0c79977/docs/research/2026-10-22-planning-site-impact/commerce/README.md)、[Genie/项目保存与运行](https://github.com/AssassinFlash/de-linker/blob/d776d015429c39d5857ee4c9ac21ca22ed2f6f91/docs/research/2026-10-22-planning-site-impact/genie-projects/README.md)。三份报告分别核查24、36和60个固定源码引用，属于静态依赖证据，不表示这些路径本轮动态验收通过。

已追到的关键断点/新合同失配包括：

当前营销LC正文、商品FAQ、数据库SEOPress配置，以及实际历史项目数量/文件完整性尚未做生产只读盘点。施工前必须取得相应存储对象和渲染读回，不能用仓库全文搜索代替全站数据清查。

## 4. 全站共用的交接合同

以下为新合同的设计语义，不是声称当前接口已经具备这些字段。

### 入口与项目

入口意图包括目标工作区、已有商品选择/输入、来源页和呈现语言。项目已存在时携带受控项目引用；新项目则以明确的初始化意图建立。白名单、单位、国家与来源在服务端校验，URL中的项目编号不代表访问权限。

解析链必须经过“公开入口/旧地址 → WP挂载与网关 → 应用初始化 → 项目保存”各层。只在React读取一个PHP没有输出的字段不能修好深链。语言切换需保留相同项目与工作区，国家始终来自项目资料。

### 结果与历史

项目、输入修订、一次计算、选中候选和文件分别有身份。工作台、账户、Genie、报告与商务按引用读取同一冻结结果。输入变化产生新修订并标出受影响结果；旧报告及已提交询盘保留原始快照。

执行成功、工程可行、输入是否最新、文件是否生成和询盘是否接纳分别记录。所有消费者使用这些实际状态，不把一个HTTP成功或按钮点击当成全部完成。

### 工程清单与商务

交接固定项目/修订/计算/候选、完整工程BOM及对应Woo商品、必需附件、非公开工程项、待核项与资产。普通商品行继续按Woo管理；工程项不能因没有公开组件商品而被静默丢掉。

handoff准备和真实提交询盘是不同动作。重复准备/提交使用可回读的幂等回执；原生询盘接纳与通知仍走现有链。用户先前手动放入的相同SKU、另一个项目的数量和本项目完整交接需要可区分。

报价/询盘时读取Woo当前商品、价格、库存和账号状态。商务变化显示具体差异；影响工程能力的替换或数量变化回到项目修订/重算，不能只改清单后沿用原“通过”。

### 归属、私有文件与生命周期

访客会话、账号和团队访问由服务端验证；访客登录后只认领自己的项目，失败须能恢复。规划数据不另存一套账号密码。新增私有屋顶/图纸/负荷资产、报告和工程引用需要进入实际保存、授权读取、保留、导出/删除与备份恢复流程。

当前代码的POST请求保护不是新GET项目/文件读取的归属校验。现有同意、隐私、通知复核和服务边界与新资产/动作的关系须逐项验证；项目引用不能当作普通公开来源URL塞入联系留言。

## 5. 旧数据和旧链接怎样迁移

站点内容先按对象ID、语言配对、来源、旧工具引用和目标落点盘点LC正文/模板、商品与FAQ、SEO/schema配置，并核当前渲染head与公开链接。

项目数据同样先做只读盘点，按真实内容识别旧记录：有完整输入/报告的计算记录、输入不完整的旧方案、只保存商品选择的记录、访客待认领记录，以及已经进入询盘/文件的历史引用。迁移目标是保留客户工作和事实，不能只凭旧`kind=residential`创建一个“新引擎已通过”的项目。

- 保留原始输入、已有商品、报告文件和来源版本；缺失屋顶、气象或规则足迹时明确无法恢复的部分。
- 能迁移为项目的记录建立新身份及旧ID映射；需要用户补充的内容仍可查看/继续完善。重新计算明确生成新结果，不改旧PDF或旧询盘。
- 访客认领先持久确认，再删除或标记已消费的原会话待领记录；失败/重复操作有回执和恢复路径。
- 保存商品选择仍作为客户选择保留，不补造邮编、负荷、屋顶或工程判断；可以在同一工作台中开始完善项目。
- 公开工具URL、旧书签和历史方案链接都有明确落点；私有项目/报告只在正确归属下恢复。
- 切换覆盖项目数据、引用文件和任务状态；回退前核对新数据格式是否可读，必要时前滚修复/保留只读访问，不把代码symlink回退当成数据已经回退。

这张只读盘点及真实迁移演练应在实施隔离实例上完成。本研究没有查询或导出客户记录，未报告虚构的迁移数量。

## 6. 同一轮实施怎样安排

1. 先固定项目/结果/入口/交接合同及参考用例，取得当前代码和运行基线，列出所有真实消费者及版本要求。
2. 在新工具设计时同步制作站点入口与交接原型：从首页或产品进入、设计、保存、报告、草稿和询盘确认；展示缺项、失败、重试与历史恢复。
3. 实现新内核、项目持久化与网关时，同步实现各消费端适配及旧记录/链接迁移；每条影响由其原模块承接，不在新工具外复制第二套工程逻辑。
4. 在同一隔离站点完成下面的真实路径和数据回读；工程准确度与消费者一致性分别通过。
5. 发布前形成同一可核查的兼容/备份/回退清单；按本地、评审站、线上读回顺序交付。修复因重构产生的站点失配后，再将重点入口导流到新工具。

当前地图仍在研究、原型和重建设计阶段。用户本轮明确的修复要求已经纳入后续同轮实施范围；本文完成不代表新工具或这些站点修复已落地。
