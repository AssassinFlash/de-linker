# 一个统一的方案设计工具：项目工作台与全欧洲目标

日期：2026-10-22。本文记录本轮真实对话中明确的产品关系和新增界面方向；属于设计资产，不是业务实现或上线声明。

## 1. 已明确的要求

用户在理解屋顶设计与系统配置的关系后明确：

> 我认为如果是听你这样说，那就没必要拆了，我们的客户也包含安装商，就是说没必要硬区分

随后提出视觉方向：

> 我认为我们可以结合我们的那个blog原型去看的，就是有点像做成dashboard的感觉。

同时，用户要求把老板此前反馈纳入：重点展示屋顶工具、做到全欧洲。老板此前仅认可想法，未批准现有UI、计算或页面布局。

据此确定：

- 一个统一方案设计工具，当前名称沿用 Solution Configurator / Lösungskonfigurator。
- 屋顶布局、发电、负荷与储能、设备配置、方案比较、报告与清单在同一个项目中工作。
- 安装商、EPC、经销商是使用者；住宅、工商业是项目背景。客户身份不决定能否访问某项设计能力。
- 全欧洲是目标，覆盖国家清单须包含非欧盟欧洲市场；项目国家、数据与规则独立于界面语言。
- 界面方向采用项目工作台。已定位并实际查看Linker Journal桌面截图及原始平台参考；保留其左侧导航、中央主区、右侧辅助区和站点视觉语言，针对设计任务改变内容与空间分配，具体视觉仍待下一版原型验证。

用户已明确统一工具及工作台方向；具体视觉、交互、命名文案、算法适用范围和工程精度仍待对应原型及验证，不写成全部已批准。

## 2. 客户怎样使用

用户进入同一个工具，根据已有资料开始：

| 客户当前要做什么 | 从哪里开始 | 可以继续到哪里 |
| --- | --- | --- |
| 看一个屋顶能怎样布置光伏 | 地点、尺寸/图纸/可用自动屋面、组件布局 | 保存布局；补充负荷、配置设备、比较整套方案 |
| 已有光伏，准备增加储能 | 现有设备、已有光伏规模/可用发电资料、用电与目标 | 验证储能方案；需要时补充屋顶信息 |
| 从头规划光伏与储能 | 地点与项目目标，按资料情况逐项完善 | 同一项目中的布局、能流、设备方案、报告和询盘 |
| 暂时只需一项成果 | 相应工作区 | 保存已成立的成果，之后继续该项目 |

工作区之间可以回看和修改。修改组件、布局或负荷后，相关结果显示需要重算；历史版本和已导出的报告保留原依据。用户不通过复制一个kWp或重新填写另一张表衔接两项工作。

住宅/工商业背景可推荐适合的负荷输入和检查事项，但不作为两套独立表单、状态和选型真相。实际项目目标，例如提高自用、削峰或备电，决定所需输入与适用计算方法。

| 区域 | 应承载的工作 |
| --- | --- |
| 顶部项目栏 | 当前项目、地点/国家、保存状态、计算状态与相关动作。切换工作区不丢失这些上下文 |
| 左侧导航 | 项目概览、屋顶与光伏、用电与储能、设备方案、结果比较、报告与清单。客户按需进入同一项目的各部分 |
| 中央工作区 | 屋顶阶段给足地图/三维及布局空间；负荷阶段看输入与曲线；设备阶段配置和比较方案；报告阶段预览成果 |
| 按需出现的属性/检查区 | 选中屋面、阵列或设备后的参数、单位、错误、计算依据、来源和待确认项。窄屏折叠，不挤占主要操作空间 |
| 新手引导 | 在当前工作台中提示下一步和结果预期；已有经验的安装商可以直接编辑，不必每次重走固定向导 |

项目概览用于说明“已完成什么、还缺什么、下一步做什么”。尚未计算时显示待补资料与入口；统计卡、曲线和绿色通过状态只能来自相应真实结果。工作台需要支持实际编辑和修改恢复，不能仅把现有表单围上一圈导航。

移动端保留同一项目与任务关系，工作区切换和属性编辑使用适合触控的控件；原型须验证画布之外的精确输入和错误恢复路径。

## 4. 屋顶重点展示如何与统一工具并存

- 网站导航保留一个方案设计工具入口，不把Roof planning与Solution Configurator陈列为两个并列软件。
- 首页重点区域可以直接展示屋顶布局预览，点击后进入同一工具的屋顶工作区。
- 住宅/工商业内容页、安装商页、产品页、博客可携带已有地点、目标或选中设备进入同一项目。
- 客户先做屋顶后继续设备配置，或从已有系统回看屋顶，项目数据和结果版本始终保持一致。

首页与相关内容的改动沿用既有网站视觉约束，记录具体导流变化；用户给出的blog原型参考只指导当前工具设计，不构成改版所有博客页面的授权。

## 5. 全欧洲必须落实到哪些地方

全欧洲按明确国家清单和功能验收，包含英国、瑞士、挪威等非欧盟欧洲市场；不能用EU成员国清单替代全部目标市场。清单和逐国验收属于后续实现规格，不声称本轮已逐国完成。

1. **项目与人工建模。** 各国地址/坐标、邮编格式、米制尺寸、图纸校准、投影和时区均有正确语义；新系统没有结构性的德国邮编/坐标绑定。每个目标国家都应有可完成项目的基本路径。
2. **地图和自动屋面。** 区域来源、时间、精度和许可分别记录。自动数据不可用时保留项目，提供尺寸/图纸等可用输入；不把建筑足迹冒充真实屋面，也不保证每栋建筑都有同等自动三维数据。
3. **发电与用电。** 当地气象、实际阵列、负荷时区/采样和方法适用域进入计算；德国住宅参考表不替代全欧洲光储时序。
4. **设备与当地规则。** 产品/模式/端口、地域放行、并网和相关工程依据按项目国家及现场条件验证；不能只改国家名称继续套德国阈值。
5. **覆盖与成果说明。** 公开说明哪些能力在各国已验证。关键依据未完成时继续建设和补证，成果准确标出当前可证明的结论；不能用一行免责声明把未完成覆盖说成已覆盖全欧洲。

英德界面和全欧洲项目范围分别验证。一个法国项目在英文或德文界面操作，仍使用该项目的法国地点与适用依据。

## 7. 下一版原型的验收问题

- 从首页屋顶入口和从已有设备入口，是否都能辨认这是同一个工具、保留同一个项目？
- 不先理解工具名称的新用户，是否知道当前要补什么、能得到什么、下一步去哪？
- 安装商能否在屋顶、负荷、设备与报告间回看修改，所有相关结果能否正确标为待重算？
- 住宅与工商业是否都能使用屋顶能力，缺时序的项目是否准确说明当前可计算内容？
- 切换欧洲国家后，地点/气象/规则及待核项是否同步变化，界面语言是否保持独立？
- 项目概览是否显示真实工作进度、计算版本和缺项，是否避免未算先出现的统计数字？
- EN/DE、1440/390下，工作台导航、主要工作区、属性编辑、失败恢复和报告是否可操作？
- 工具工作台的视觉是否确实对应已定位的Journal参考；比较左侧导航、内容层级和站点一致性，同时验证编辑空间与信息密度适合设计任务。

当前只确认产品关系、全欧洲目标和工作台方向。已有概念原型不作为下一版视觉已通过的证明；当前原型与站点入口问题继续保持打开。
