# Jev 询盘分类与耗时实测

本报告目录沿用研究开始日 2026-10-21；正式请求发生于 2026-10-21 15:58:03–16:02:11 UTC（北京时间 2026-10-21 23:58:03 至 2026-10-22 00:02:11，结束时间按最后一次起始时间加实测耗时取整）。

## 实测结果与建议

Jev 可以继续作为“只提示、不拦询盘”的初步判断候选。本次 30 条固定合成询盘各跑两轮，共 60 次；16 条正常询盘的 32 次调用均返回 `normal`，10 条明显滥用的 20 次调用均返回 `suspected_spam`。这没有证明生产环境不会误判。

4 条边界样本中，3 条在两轮均返回 `uncertain`；另 1 条普通但含糊的商务邀约在两轮均返回“分类正常、依据却是群发推广”。这个实际冲突说明结果不能直接照搬成垃圾邮件结论。建议代码遇到分类与依据冲突时显示“未能判断”，仍照常通知；本研究没有实现该映射，也没有验证邮件故障处理链路。

正式请求完整往返耗时 p50 **3.993 秒**、p90 **5.457 秒**、p95 **5.617 秒**，最慢 **5.902 秒**。若等 5 秒，60 次中会有 10 次还没返回；8 秒和 10 秒在本批次均可等到全部 API 响应。建议把 **10 秒作为观察阶段内部团队通知的初始等待上限候选**，给本次未测的调度、序列化等开销留一些余量。它尚未获得业主对具体秒数的确认，也尚未实现；本机小样本不能证明生产 10 秒必达。

客户提交应先持久化成功并返回，Jev 放到后台。内部通知可在结果提前返回时立即生成；到有界期限仍没有可用判断，则带“未能判断”照常发送。晚到结果只补后台记录，不补发第二封邮件。这个期限应从提交保存成功后计算，排队和附件提取都会消耗同一个总预算；模型耗时不能冒充端到端耗时。模型失败、任务未启动、附件未读或分类冲突时都必须有独立可执行的通知兜底。本次没有测试这些应用机制。

## 固定试验设计

- 样本在调用前固定：16 条正常、10 条明显滥用、4 条边界，英/德/俄语；每条重复两轮，第二轮逆序。并发数 1，无自动重试。
- 期望标签由研究者人工编写并在结果前固定，没有经业主逐条独立裁定，也不是来自真实客户的人工金标。不能把本次一致度称为生产准确率。
- 4 条边界预设首选 `uncertain`，同时预先允许 `normal`，目的是不凭含糊内容升级为垃圾。正常投诉、退款/付款询问、短留言、陌生公司、非核心业务、供应商合作、语言和合法链接本身均不构成垃圾依据。
- Jev 读取本次提交已有的全部合成字段：联系人、公司、账号状态、正文、产品行、相关对话和已解析附件文字；缺失对话和附件提取失败均显式标记，没有假装已经读完。原始附件、OCR/PDF 解析没有进入本次测量。
- 所有姓名、联系人与业务记录均为合成；邮箱使用 `example.com`，链接使用惰性的 `.invalid` 示例域。没有读取生产客户原文，没有访问样本链接，没有发邮件。
- S01 改写了业主提供的俄文转账诱导，并把真实 URL 替换为 `https://claim.example.invalid/ab8fPRx1`。它不是对原始 URL 或发信来源的复测。
- 两个 typed choice 问题：`classification` 只选 `normal` / `suspected_spam` / `uncertain`；`basis` 只选固定依据类别，不生成自由文本解释。rubric 明确将提交内的指令和身份声称视为待判断数据。
- 研究请求使用 urllib 的 30 秒连接/读取超时，无自动重试。这是研究预算参数，不是已经选定的生产超时；它也不是严格覆盖 DNS、所有读取步骤的总墙钟 deadline。正式 60 次均未触发超时。
- 本次仅经 `https://openrouter.ai/api/v1/systemone` 调用 `typesafe/jev-1.13`，60 次实际返回的模型均为 `typesafe/jev-1.13-20260917`，provider 均为 TypeSafe。脚本拒绝其他/缺失模型标识，没有改通道或降级。

固定版本：`inquiry-observation-v1`。以下 SHA256 使用排序键、紧凑分隔符、UTF-8 的规范化 JSON，而非缩进文件的字节 SHA：

| 对象 | SHA256 |
| --- | --- |
| `cases.json` | `20731251f92489cae777badd6411ea079ccafb97e800b96ba72715f62adcd822` |
| `rubric.json` | `de7a8e622b80c8721f7a8170eecf04eb250f7f107c488badd9ddb7e9597fef6f` |

先做的 3 次探测单独保存在 `raw/probe.jsonl`，没有混入正式 60 次；它们均为正常样本，耗时 3.340 / 3.743 / 4.623 秒。父会话另做了一次不同单问题的连接探测，其结果不在本数据集中，不参与本报告统计。没有边看答案边修改正式 rubric 或期望标签。

## 分类、安全误标与稳定性

| 预设类别 | 独立合成样本 | 两轮调用 | 实际 raw classification |
| --- | ---: | ---: | --- |
| 正常 | 16 | 32 | 32 normal；0 suspected_spam；0 uncertain |
| 明显滥用 | 10 | 20 | 20 suspected_spam；0 normal；0 uncertain |
| 边界/信息不足 | 4 | 8 | 6 uncertain；2 normal；0 suspected_spam |

以预设的首选三分类逐调用比较为 58/60 一致（96.7%），两个差异均为 U03 的 `uncertain → normal`；由于 U03 预先允许正常放行，60 次均在预设允许标签内。**这些数字只是这组固定合成夹具的吻合情况，不是真实客户分类准确率。** 两轮不是 60 个独立客户样本。

安全维度单独看：本组 16 条正常样本没有观察到 raw classification 被标为 `suspected_spam`；本组 10 条明显滥用样本没有观察到漏为正常/不确定。样本量与难度都不足以给出生产误判率或漏判率。

30 对 raw classification 在两轮中全部相同。重复稳定不代表正确：U03 的矛盾依据也稳定重复。具体输入为：

> Wir haben ein interessantes Angebot für Ihr Unternehmen. Melden Sie sich, wenn Sie mehr wissen möchten.

两轮均为 `classification=normal`、`basis=unsolicited_bulk_promotion`。这句没有证明群发；若把依据直接翻译为“群发推广”，就会制造没有证据的提示。应用层应检测“正常 + 滥用依据”或“疑似垃圾 + 正常/信息不足依据”的冲突，并映射为“未能判断”。本报告据此分析，未改写 raw response。

本批次有 6 个语义 `uncertain` 响应，加 2 个分类/依据冲突，共 8/60 应在业务上视为“未能判断”。API 成功及时返回与语义能够判定是两件事。返回的 confidence/probabilities 也没有做真实客户校准，本报告不拿它们设自动拦截阈值。

## 耗时、输入规模与候选期限

测量从每次即将执行 HTTP POST 到响应体读取完成的 `perf_counter` 墙钟时间，包含本机发往 OpenRouter 的网络及服务端响应等待。没有复用长连接；每次用 urllib 新建请求。它不包含 WordPress 持久化、任务排队、附件抽取、通知模板生成、Outbox 排队或邮件投递。百分位使用最近秩法 `ceil(n × p)`。

| 范围 | 次数 | p50 秒 | p90 秒 | p95 秒 | 最大秒 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 正式全部/有效请求 | 60/60 | 3.993 | 5.457 | 5.617 | 5.902 |
| 首轮 | 30 | 3.993 | 5.485 | 5.757 | 5.902 |
| 复跑轮 | 30 | 3.901 | 5.069 | 5.569 | 5.636 |
| state 小于 2,000 字符 | 56 | 3.993 | 5.485 | 5.636 | 5.902 |
| state 为 2,000–9,999 字符 | 2 | 2.937 | 3.431 | 3.431 | 3.431 |
| state 至少 10,000 字符 | 2 | 4.546 | 5.457 | 5.457 | 5.457 |

state 字符数按 Python JSON 序列化文本计算；实际 state 为 325–15,623 字符，完整请求体（含 rubric）为 2,830–18,123 UTF-8 字节。N14 的全上下文包含联系人、账号/公司/地址字段、两条对话和产品行，state 653 字符。N15/N16 分别含 5,000/15,000 字符的合成附件提取文字，state 5,563/15,623 字符；各只有两次调用，且长文字重复、内容简单，无法据此推断长附件不会变慢或模型一定理解了全部细节。

HTTP 错误 0、超时/网络错误 0、JSON/协议/选项错误 0、错误/缺失模型 0。没有实际故障样本，所以没有证明应用的失败通知机制有效。

以下是把观测耗时代入候选等待期限后的**离线重算**，没有在运行时取消请求。任何真实 HTTP/解析/模型错误均应计为“未能判断”，本批次此类错误恰为 0：

| 等待上限 | API 在期限内有效返回 | 超时或调用错误而未能判断 | 比例 | 再计语义 uncertain/冲突后的全部未能判断 |
| --- | ---: | ---: | ---: | ---: |
| 2 秒 | 0/60 | 60/60 | 100% | 60/60 |
| 3 秒 | 5/60 | 55/60 | 91.7% | 55/60 |
| 5 秒 | 50/60 | 10/60 | 16.7% | 16/60 |
| 8 秒 | 60/60 | 0/60 | 0% | 8/60 |
| 10 秒 | 60/60 | 0/60 | 0% | 8/60 |

2–3 秒会使本组大多数结果赶不上首封通知；5 秒已有明显损失。8 秒与 10 秒在这 60 次 API 调用上的覆盖相同；选择 10 秒只是初始工程余量建议，不是尾部风险的统计保证。由于还没有生产排队/附件解析数据，上线实现必须观测端到端延迟及未判定原因，不能把 60/60 写成生产 SLA。

## 模型用量与费用

60 个正式响应均返回 usage：合计 input_tokens **68,636**、output_tokens **8,456**，响应 `usage.cost` 合计 **USD 0.002882712**。3 次探测的返回费用另计 **USD 0.000122346**，不混入正式用量。以上仅是这批响应报告的费用字段，不是账户账单对账，也没有包含父会话的独立连接探测。

## 能支持与不能支持的结论

本次支持继续设计一个异步、只提供标签的 Jev 观察阶段，并用保守的未判定兜底保护所有客户询盘。本次也实际揭示了“正常商务语句被依据字段误称群发”的冲突，必须由确定性代码处理，不能只展示一个看似明确的模型理由。

本次没有评估原始诈骗邮件究竟从网站入口还是直接邮箱投递，没有访问真实恶意 URL，没有接入真实表单/注册/Genie，没有实现后台任务、10 秒期限、超时通知或晚到更新，也没有部署。它不能证明真实误判率、抗攻击强度、生产尾延迟或客户提交不受影响。

合成样本较容易：输入包含 `synthetic_fixture` 标记、保留域链接，部分滥用样本自述“群发”、诈骗诱导也很明显；多数公司字段相同，缺少真实客户表达噪声与攻击者长期适应。提示注入只覆盖 1 条显式指挥分类器的案例，虚构 approved 身份也只覆盖 1 条；它们通过不代表所有注入都能抵抗。长附件只测合成提取文字，没有测真实图像/PDF、复杂表格、多文档矛盾或吞吐。

## 证据与重跑

本报告性能与行为结论的直接证据为本目录的实际 API 返回：

- `cases.json`：调用前固定的完整合成输入、首选标签与允许标签。
- `rubric.json`：调用前固定的两个 typed choice 问题及规则。
- `raw/formal.jsonl`：60 次原始响应、model/provider、usage、墙钟耗时、输入规模、轮次；所有成功响应均原样保留。
- `raw/formal.jsonl.manifest.json`：端点、模型、SHA、超时、并发、无重试与标签来源声明。
- `raw/probe.jsonl` 及 manifest：单独保存的 3 次探测。
- `summary.json`：脚本从正式 raw 数据重算的指标和每条两轮明细。
- `pilot.py`：输入生成、限定通道调用与计算脚本；不会向邮件/生产服务发请求，不会访问样本 URL。

在本目录运行（需要 Python 3，密钥从 `OPENROUTER_API_KEY` 或现有 `~/.config/terravolt-builder/openrouter.env` 读取，不能把密钥写入参数或报告）：

```sh
python3 pilot.py prepare
python3 pilot.py run --output rerun-YYYYMMDD.jsonl
python3 pilot.py summarize
```

`prepare` 拒绝覆写不同的固定输入；`run` 拒绝覆写已存在的输出。`summarize` 默认重算这次 `raw/formal.jsonl`，不自动混入重跑文件。若要研究新 rubric，应复制成明确的新版本并独立计算，保留本轮初版，不在答案已知后改变本轮期望值。
