# 文档与知识索引

本规格落实[统一产品与资料发布规则](609-product-publication.md)及业主 2026-10-24 再次确认的目标：只在 WooCommerce 维护产品、资料及关联，Genie 与其他工具自动跟随。研究依据保留在 `docs/research/2026-10-09/knowledge-audit.md`、`embedding-bakeoff.md` 与 `docs/research/2026-10-17-knocket/TRIAL.md`。

## 来源与权限

构建输入只来自 Woo 当前 publication manifest。只处理已发布销售产品具有有效公开关联的托管 PDF；媒体库全量扫描、另一份产品表、品牌名单及旧索引都不授予权限。按 SHA 复用下载、解析与向量缓存；不同 URL、资料身份、产品关联的公开权限分别判断。工程参考组件不进入 Genie 销售产品范围。

产品、媒体记录、原版文件和客户历史保留。资料里同时出现上架和未上架型号时，原文件可以继续为有效关联提供下载，工具的答案只使用当前产品适用的内容。撤权立即生效，不等待解析、构建或定时任务。客户当前页面由页面读取能力独立获取；营销页、FAQ 和模型编写的说明不进入 PDF 知识索引。

## 自动处理

Woo 的正常保存通过已有持久任务队列产生待办；Mac 的受管 worker 每次也对账当前源，离线或漏事件不丢失更新。完整作业为：

```text
Woo 当前产品与资料版本
  → 领取带 recipe 和 activation_epoch 的租约
  → 校验原 PDF 字节 → Docling 原生页、段落、表格单元格
  → 编译当前型号适用片段 → embedding → SQLite
  → 新鲜租约检查及受保护的原子切换
  → 实际服务进程 loaded 读回 → Woo 确认
```

解析在 Mac 运行；VPS 不运行 Docling、OCR 或文档编码模型。成功解析缓存同时绑定 PDF SHA、Docling 版本和解析程序/依赖指纹。失败、缺页、损坏 JSON、缺失必需 OCR 输出均重新处理；失败尝试不能复用上次残留输出冒充成功。完整有效的成功缓存可复用。

分块上限沿用 512 个 XLM-RoBERTa token；实际 `BAAI/bge-m3` tokenizer 的已验证提交和内容摘要固定在 `index/tokenizer.py`，不追随上游 main。表格、页码和原生来源坐标保留；长表按行分块并重复必要上下文。型号投影必须在向量计算前完成，索引与 embedding 使用完全相同的最终文本。

默认编码保持 gemini-embedding-2，只经 OpenRouter；通道及失败策略遵守项目裁定。SQLite FTS5 + sqlite-vec 是服务唯一在用索引，路径为 `/opt/linker-genie/index/current/index.sqlite`。MariaDB SQL 仅保留离线导出能力，不引入第二个运行时知识源。

## 资料适用性编译

厂商原版 PDF、Docling 缓存和原始片段保持原样。原有整段及整表证明继续遵守原有严格规则。新的派生答案单元采用独立证明：

- 参数表按当前精确型号只投影该型号列、原始属性名、原始值和必要小节上下文；不把另一列数值交给模型后要求其自行选择。
- 证明绑定原生表身份、页码、单元格顺序及行列范围、文本摘要、物理坐标和当前资料关联。合并型号表头只有在原文件可见文字坐标能逐一确定对应列时才使用；裁切区外隐藏文字不参与。不能按合并字符串的阅读顺序猜列。
- 原生逻辑行错位、跨行不明、脚注无法确定适用对象、未知型号和混合范围的个别行拒绝。其他已证明的行仍可使用，不把整本资料误报为全无知识。
- 手册的厂商系列标题配合 Woo 当前明确关联，可为系列内产品编译共同说明。系列前缀从当前型号自动推导；更细型号覆盖、未知型号、另一系列与参数表不得通过这一规则广播。
- 每个派生单元只面向对应当前型号。下架另一型号不撤销本型号未变的有效说明；本型号撤权、移除资料关联或更换字节后，旧证明立即失效。

构建、SQLite 准备及运行时检索共用重建/校验规则。修改投影文本、来源、行列、表头或关联均拒绝。不能只改准备计数、降低证明要求或手工补一张型号表。

## 三种状态

Woo 发布许可、处理完成和问题可回答范围各有含义：

| 状态 | 含义 | 自动行为 |
| --- | --- | --- |
| 当前发布许可 | Woo 允许此产品及资料关联被客户读取 | 每次读取和输出前核验，撤下立即拒绝 |
| `materialization_complete` | 当前全部输入已成功处理 | 成功代次可结束队列作业；失败解析保留重试 |
| `preparation_complete` / 已证明产品集 | 当前关联有可用于回答的证明片段 | 保留真实缺口和原因，不由处理成功推断 |

`no_proven_passage` 是处理后的语义诊断，保留在 loaded 和 Woo 收据中；它不制造产品准备许可，也不要求相同输入和处理规则永久重复构建。`document_unparsed` 则继续待办并真正重试解析。发布产品仍可被正常发现和展示，具体技术回答必须有对应依据。

## 代次、实际执行与恢复

`recipe_revision` 自动覆盖构建、编译、运行时证明规则、发布程序和锁定依赖。只有代码或处理规则改变而 Woo 内容不变时，同样自动产生新作业。解析缓存另有处理程序身份。产品及 source revision 不包含准备状态，收据不会导致 Woo 源循环变化。

索引记录预期 `serving_revision`；进程在启动时从不可变发布目录实际计算自身规则身份。`/knowledge/loaded` 分别报告二者，不能只凭 SQLite 自己声明的 recipe 就证明运行时匹配。受管索引的预期规则与实际进程不一致时，检索及片段授权立即拒绝；loaded 诊断仍可读取，供自动任务发布匹配的替代索引。确认同时核对当前 Woo source、recipe、实际 serving、索引代次、activation epoch 和精确已准备产品版本。

每次新租约在原生锁中取得严格递增的 activation epoch，源变化、重试、代码更新及恢复均不归零。远端在排他锁内核对索引、实际运行规则和新鲜 Woo 租约；先持久记录 epoch 与目标，再原子切换。晚到的较低 epoch 不能替换已接受的新代次；同 epoch 只允许完全相同目标恢复中断。每次普通轮询都读取实际服务，即使 Woo 显示 ready；代次漂移通过原生锁中的当前收据比较重新排队。

回滚继续服从当前 Woo 许可。受管索引不直接把 current 指回旧 epoch；确认既有处理规则的真实指纹后，内部 CAS 重新激活已知旧 recipe，用当前 Woo 输入领取更高 epoch 并自动准备。详细命令和边界见 `services/genie/ops/PUBLICATION.md`。

## 检索、数字与引用

Genie 只读服务进程中的 SQLite。检索先取当前 Woo 范围，并将片段证明与当前产品、资料身份、版本及关联求交。型号圈定、全库回退、相邻片段、短数据手册扩展及最终引用全部执行相同许可和适用性规则；明确产品范围为空时不扩大到其他产品。

有匹配查询编码器时只走向量排序，编码失败显式报错；所在主机没有查询编码器时才使用 BM25。模型只引用片段 ID，文档数字以事实占位符由服务端填入。引用链接和页码由服务端生成，输出前再次检查当前资料许可；投影里的数值必须对应投影后可见的正确参数行。

## 验收

- 当前 manifest 的全部有效 PDF 均处理，失败逐份报告；原始文件摘要不变。真实受影响产品逐型号验证参数、安装说明和页码，不能只验准备数量。
- 共享表里的未知/下架列、被篡改的证明、已撤关联、同 SHA 不同权限域、旧索引及全库/邻块回退均不得泄漏失效产品事实。
- Woo 正常保存自动经历领取、构建、发布、实际加载和确认；代码单独升级同样生效。失败后同 SHA 再次真实解析，语义缺口稳定后不永久重建。
- 当前索引与旧服务规则不匹配时拒绝发布/确认；旧任务在新任务完成后晚到、进程中断、租约到期和当前代次漂移均能安全拒绝或自动恢复。
- 保留既有召回及回答评测，对比时报告当期有效产品范围；已撤产品必须作为拒绝样例，不能用历史产品召回要求扩大当前许可。客户实际问题按 Knocket 对照的答案正确性标准核实。
- 全量 Spec/Standards 双评审、真实 WordPress 锁与队列夹具、EN/DE 实际客户回合、390/1440 状态截图，以及生产进程与收据读回。源码和单元测试通过不代表部署完成。
