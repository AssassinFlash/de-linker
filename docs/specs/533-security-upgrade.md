## 已确认的事件

05:45–06:37:57 UTC 的 88 条记录中，87 条是同一诈骗活动，1 条是此前授权的受控验收记录。88 条都由正常访客联系入口写入原生 Woo 询盘，并有匹配的完成准入凭据。攻击轮换浏览器身份和邮箱，已观察的连接桶未达到 100/hour；没有发现原子额度绕过。现有策略没有把活动总量、邮件容量与廉价身份轮换联系起来。

应用邮件 80/滚动 24 小时预算被耗尽，38 条等待通知均独立匹配同一活动。实际内部通知走已配置的认证 SMTP；应用仍对所有邮件共用同一节流。52 次初判超时均在模型开始前已排队至少 10 秒，不能据此认定 Jev 推理慢。

06:38 UTC 临时恢复强制验证；06:55:21 UTC 可恢复暂缓 38 条已确认活动的待发送通知。07:53 UTC 读回仍为 held/private，匹配待执行或运行中的动作数为 0。07:57:53 UTC 询盘仍为 88 条。缺少被拒尝试的完整分母，因此这不证明攻击停止或真实客户误拒率为零。

自有源码、已发布依赖、MU 与缓存核心逐文件一致，uploads 无所查可执行扩展，账号 ID/角色与事前备份一致。没有证据把本次表单活动归因为 PHP RCE 或管理员失陷；共享主机访问/认证日志和第三方组件审计仍不完整。

事实依据分别保存在 [入口调查](https://github.com/AssassinFlash/de-linker/blob/54a8c235/docs/research/2026-10-22-incident-forensics/DOSSIER.md)、[通知与排队调查](https://github.com/AssassinFlash/de-linker/blob/d805262a/docs/research/2026-10-22-incident-delivery/DOSSIER.md)。原始业务数据、凭证与完整备份仅留本机私密目录，不入库。

## 客户接收合同

| 情况 | 客户实际获得什么 | 后台和资源行为 |
| --- | --- | --- |
| 正常验证完成、非人工确认活动 | 原生询盘持久化后的真实接收状态；不等 Jev | 有界后台分类；超时“未能判断”，仍通知团队 |
| Jev 单独标疑似垃圾 | 仍保留已接收询盘 | 标签供人工判断；不据此拒收、删除或自动暂缓 |
| 联系/询盘的第三方验证无法完成 | 独立容量内保存完整待核验记录，显示真实待核验状态及编号 | 不冒充 verified；不调用模型、不向任意提交邮箱回执、不逐条消耗即时通知；员工可恢复 |
| 人工确认的本次活动 | 有限完整可恢复样本与活动计数；只对确已保存的记录承诺保存 | 窄且可撤销的活动规则；不逐条模型/邮件；与普通待核验容量隔离 |
| 对应接收区已满或原生校验失败 | 明确未保存、保留输入/产品草稿，提供重试与团队邮箱 | 不给虚假接收编号，不消费模型/邮件，不重置账本 |

精确活动规则必须组合整段转账诱饵、金额、固定领取句式和确切落地域；正常俄语技术询盘、引用骗局求助、合法产品链接、免费邮箱或缺 VAT 不能命中。没有一种内容分类能保证零误判，必须保留独立人工判断和恢复。

接收、付费服务和邮件分别设预算。隔离区采用跨浏览器的持久占用上限，不靠每日清零掩盖累积；正常已验证接收与普通待核验、已确认活动样本分别计数。初始阈值必须根据原生字段上限、可接受积压和资源信封写明推导，不伪称行业标准或已测客户量。

本合同在 [有界接收和活动隔离](https://github.com/AssassinFlash/de-linker/issues/542) 实现和验收后替代临时强制验证。届时才能宣称具备验证失败的站内恢复路径。

以下是逐消费者验收范围，非完成声明。原有实现分别见 519、520、521 和 522 规格；必须使用当前合并发布版本重验。

| 消费者 | 最后副作用边界 | 必须证明 |
| --- | --- | --- |
| 联系、访客/登录询盘、直接 admin-post | 原生 Sender 首次保存、状态邮件 | 保存一次、接收状态准确、活动/验证故障路径、原 job 恢复 |
| Genie 联系/询盘/会话邮件 | Tools 原生 handler → 共享 Business / Sender | 同一主体不能换门重置额度；不把新普通表单 fallback 扩展成模型免验证入口 |
| Woo/core 注册、登录、找回密码 | 用户创建、外部 VAT、密码校验/重置 key 与 mail 前 | 正常登录不挑战；失败升级验证；账号审批/价格门保留；恢复邮件独立 |
| 草稿、wc-ajax、GET 命令、Store API / batch、reorder | 原生 session/cart 写入前 | 所有别名与批量子请求同样受控；只读商品浏览和草稿读不消耗写额度 |
| 评论、REST 评论、XML-RPC | 原生 comment 写入和方法映射 | 不恢复公开评论；pingback 限制确实执行；已存在认证消费者不误伤 |
| Genie turn、图片/PDF/语音/导出 | 私有服务 token、解析/供应商调用前 | 大小/实际类型/页像素/解析时限、并发和花费预留；超时不重复免费执行 |
| 配置器、屋顶、地图、报告/PDF | 真实工程/供应商 dispatch 前 | 预算和幂等在真正调用处；正常输入/附件与已有缓存保留 |
| Cron、恢复、服务回调、直接 VPS | 实际后台消费者和服务 Gate | 无浏览器也会按时执行；匿名不能付费；持久暂缓不被恢复绕过 |

## 比较指标与交付门槛

阶段分别报告原始状态、严格验证、普通表单免验证、当前应急模式、分层接收。相同受控夹具可以比较；没有完整历史分母的真实转化率不补造。

- 客户：按语言/设备/入口/账号状态记录尝试、成功保存一次、待核验、明确未保存、人工恢复、输入/草稿保留。
- 活动：独立人工真值、匹配/误归组/漏过、完整样本与计数、实际新增邮件/模型调用。Jev 自己的标签不是真值。
- 时效：客户提交耗时、排队等待、模型时间、首次通知标签覆盖率、队列最老年龄和恢复时长分开。
- 资源：持久占用、并发预留、已发生花费、拒绝原因与重试时间；服务故障不记为客户恶意。
- 邮件：原始 job、计划时间、attempt、SMTP 接受、退信与指定主邮箱收件分开；queued 不写 sent。

每个发布必须有精确完整 diff、Spec/Standards、改动层原生夹具、需要的 Computer Use 状态、本机备份、生产读回和回滚。测试邮件继续只限本地/授权单一 tester，不为凑数量反复实发。

代码回滚保留新询盘及元数据；回退持久暂缓旧发送器前继续精确取消对应回调。配置回滚恢复原字节和权限。边缘规则逐条撤销且保全邮件解析。PHP 不回退到已知未修补构建。完整 goal 只有上述范围验收或业主明确裁定排除后才可完成。
