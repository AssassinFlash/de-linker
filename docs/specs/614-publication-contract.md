# Current Woo publication contract

Implements the approved [product and document rules](609-product-publication.md). The contract owner is `Linker\Commerce\Products\Publication`; generated feeds and preparation receipts never grant publication rights.

All routes use `/wp-json/linker/v1/publication/`. Public reads send `Cache-Control: no-store, private, max-age=0`. Consumers must obtain a fresh response before candidate selection and validate the complete dependencies again before returning output or committing a new action. An unreadable authority stops the affected operation.

- `GET manifest` returns `schema_version: 1`, stable `source_revision`, `compatibility_revision`, `products`, and `documents`. Products contain `product_id` (canonical), `product_revision`, public `title`, `model`, `brand`, `locale_product_ids`, `published_locale_ids`, document IDs in `documents`, and `ready: {knowledge, engineering}`. Documents contain `document_id`, `document_revision`, `blob_sha256`, `url`, `aliases`, active canonical `product_ids`, `title`, `type`, and `lang`. Unpublished product facts do not appear.
- `POST validate` accepts `{products: [{product_id, product_revision}], documents: [{document_id, document_revision, product_id}], compatibility_revision?}`. Both lists must be explicitly present; two empty lists represent zero authorized objects. Missing revisions, unavailable identities, removed associations or mismatched revisions make the whole response `valid: false`. The response is `{valid, source_revision, invalid: [{kind, id, reason}]}`. An informational `source_revision` on input is allowed; an unrelated source change does not invalidate unchanged dependency revisions.
- `POST identify` accepts `{models: [exact model labels]}` and returns `{models: [{model, status: published|unavailable|unknown, product_id?}]}`. It reports only labels supplied by the caller, and `product_id` exists only for published identities. It never supplies draft technical facts or a complete withdrawn-model list. Public request bounds are 20 labels and 200 bytes per label.

Preparation writes require native WordPress Application Password authentication with `manage_woocommerce`. Runtime Genie/engine public permission checks do not require a WordPress identity.

- `POST jobs/claim` accepts `{consumer: knowledge|engineering, worker_id, lease_seconds}`. The lease is positive and at most WordPress `DAY_IN_SECONDS`. It returns `{job: null}` or `{job: {job_id, consumer, source_revision, lease_token, lease_expires_at, manifest}}`. Claim always reconciles current Woo state, so lost events or an offline worker do not lose work. Each consumer retains its current job and previous loaded receipt, replacing superseded work.
- `POST jobs/ack` accepts `{job_id, lease_token, source_revision, loaded_revision, status: ready|failed, error?, prepared_products: [{product_id, product_revision}]}`. Knowledge preparation must report its actual prepared set. A partial set keeps the job pending while already prepared current products remain usable. `ready` must follow a readback proving the actual running process loaded the matching output. Source changes or expired/replaced leases return HTTP 409 `stale_job`; no readiness changes. `failed` persists the reason and releases the lease for an automatic retry. Success returns `{accepted: true}`. Readiness never participates in product or source hashes.

The engineering feed adds the same `source_revision` and `compatibility_revision`; each item has `canonical_product_id` and `product_revision`; documents carry the full identity/revision/association fields. Its compatibility revision hashes the compatibility contract alone. A Woo engineering reference has its own product revision and current document dependencies, carried in `reference_inputs` whenever the calculation uses it; changing a reference does not invalidate an unrelated calculation that never used it. Consumers must additionally validate every cited document dependency; the compatibility hash itself does not grant evidence access. A `since` feed is not a revocation authority.

Document identities derive from the normalized hosted path, and content SHA is separate. Original URLs and explicit aliases stream through the current relation gate; equal SHA alone grants nothing. Native WordPress rewrite installation occurs before its existing-file shortcut and preserves emergency rules outside the WordPress marker. `wp linker-commerce publication install-gate` installs and reads back that rule; `manifest` and `reconcile` inspect/reconcile the same contract. Existing EcoFlow emergency rules must remain until separate parity acceptance permits removal.

Custom code is limited to capabilities absent in Woo: Woo natively owns products, post metadata, media and Application Password authentication; Action Scheduler owns durable notification scheduling; WordPress owns rewrite-block installation. Woo does not supply cross-process per-dependency publication revisions, preparation leases, or current authorization of existing static file URLs, so this narrow module implements those seams. No new manually maintained product source is introduced.


Internal authority queries explicitly read every language with a server-only boolean `linker_publication_internal` marker and an empty native `lang` query. The language companion skips ambient language injection only for this marker; HTTP parameters do not become this server query flag. Native Store API lists retain EN/DE scopes and additionally require canonical publication. A published German mirror cannot restore a withdrawn source. Existing native draft sessions discard withdrawn live product lines before rendering their current data; customer-owned immutable inquiry/report snapshots remain under their separate owner routes.

Each new authority read flushes only request-local object-cache copies, preserving the shared Redis database. The cache drop-in must support `wp_cache_supports('flush_runtime')` and `wp_cache_flush_runtime()`. Unsupported or failed refresh produces explicit HTTP 503 `publication_unavailable` on manifest, validation, identification and feed routes; document streaming returns 503 without bytes. Deployment must verify support in the actual production process before switching code.

Engineering facts have generated `_linker_publication_figures` bindings containing the figure fingerprint, explicit source document identity, and source bytes SHA. Normal Woo fact writes bind the changed fact; unchanged values keep their old binding. `wp linker-commerce publication bind-figures` is a one-time adoption of existing explicit Woo sources and preserves existing bindings on rerun. It does not claim a semantic re-verification of all existing numbers. Replacing PDF bytes at the same URL changes document revision and prevents old values from entering the feed, including scalar fields; parsing, readiness acknowledgements and an unchanged save cannot rebind those old values. The product editor identifies fields lacking current evidence. No additional product source or manual per-tool synchronization is introduced.


## Navigation supply fragments

The EN/DE LiveCanvas header sentence fragments derive their brand names from native Woo `pa_brand` associations of currently published sales products. `home-storage` scopes the home-battery claim; the union of `home-storage` and `commercial-storage` scopes the energy-storage claim; `commercial-storage` scopes its commercial-storage claim. Native `product_cat` queries include descendants, including future children and products assigned directly to a parent. Inverters, meters, accessories and their unrelated brands do not enter a storage claim merely by being published. The source taxonomy fixture has home/commercial storage as roots, all-in-one/battery systems under commercial, inverters as another root and meters under accessories; integration readback must confirm the deployed tree.

The fragment opens one `Publication::published_ids()` batch before any native category, visibility, stock-option or candidate read. Its candidate-reader callback preserves Woo catalog hiding and configured out-of-stock hiding; the permitted IDs additionally exclude `EngineeringReference` using the canonical role. A published locale mirror cannot restore a withdrawn source. Native `product_visibility` names (`exclude-from-catalog`, optionally `outofstock`) resolve through the current taxonomy query; the Woo helper's process-static term-ID map is not a permission source. Each independent fragment read is fresh; no static brand registry, preparation copy, manifest, document assembly or PDF read participates. The native term query is bounded to the permitted object IDs; an empty candidate/name set returns an empty fragment, never an unrestricted brand query. The LC templates own the prefix, suffix, conjunction, enclosing elements and all classes. The projection returns escaped text only.

Native-capability exhaustion: the installed LC `lc_the_terms` calls `get_the_terms()` on the current post; `lc_wc_product` calls a getter on the current `WC_Product`; neither aggregates attributes across the intersection of a category branch and current canonical permission. Woo `wc_get_brands()` and `product_brand_list` read `product_brand` and return linked term-list/brand-list markup; this site's existing fact attribute is `pa_brand`, and those entries cannot express the publication/reference intersection. WordPress `get_posts()`/`get_terms()` already supply the category descendants, catalog exclusions and attribute associations, so the custom `SupplyBrands` seam only joins their permitted names into LC's existing sentence. No extra manually maintained source or layout is introduced.

The source fixture must exercise the actual EN/DE header fragments, parent and descendant products, a newly added descendant/brand, duplicate names, source draft with a still-published locale mirror, engineering references, catalog/stock hiding, empty scopes/names, and independent rereads. Cache-shaped regressions must separate persisted category hierarchy/stock options from prewarmed runtime copies, and retain an obsolete Woo static visibility-ID map while recreating its native term. The pure-memory `tests/fixtures/supply-brands-cache.py --wordpress-root <existing WordPress root> --php <PHP 8.3 binary>` fixture extracts the installed native hierarchy functions and Woo visibility helper without booting WordPress, and can run the same cases against an earlier commit with `--source-revision`. It must fail on any document-file access. Native EN/DE render and visual acceptance remain integration gates.
