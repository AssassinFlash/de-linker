# #9 i18n：Polylang 免费版 + linker-i18n

依据：`docs/research/2026-10-09/i18n-opensource-replication.md`（功能清单与风险）、AGENTS.md §3（用词与 Sie 体）。

## Polylang 配置（由 `tools/local` 与切换脚本经 WP-CLI/REST 施加，不手点）
语言：en（默认，无前缀）、de（`/de/`，locale `de_DE_formal`）；URL 目录模式；浏览器语言检测关闭；同步：分类、标签、特色图、页面属性、菜单顺序、评论状态；媒体不翻译；字符串翻译开启。

## `plugins/linker-i18n`（PSR-4 `Linker\I18n\`，一类一文件）
- `SameSlug`：过滤 `wp_unique_post_slug` 与分类 slug，允许不同语言的翻译对使用同一 slug；按 slug 取单品/单页时按当前语言解析（修 `get_page_by_path`、Store API 按 slug 取单品）。
- `UrlSegments`：product → produkt、product-category → produkt-kategorie、shop 页 products → produkte；德语重写规则 + 反向解析；`/de/` 下的英文段返回 404（不再 200 重复页）。
- `TranslateOnSave`：英文对象保存（全部页面（含营销页）、文章、商品、分类、属性词、SEOPress meta）→ 排队任务（Action Scheduler）→ 调 DeepSeek 逐段翻译（词表 `data/glossary-de.json` 强制、禁用词 `data/banned-de.json`、型号与数字保护、HTML 结构保护）→ 创建或更新德语版对象，写翻译组；译文带 `_linker_i18n_source_hash`，源文未变不重译；已有德语无基线时原样保留并记录当前英文，不调用模型；英文变化时只更新能对齐的改动句子，未变句子及其人工德语字节保留。相邻 equal 句段可定位的新增句只翻新句并插入对应位置，删除句移除对应德语；平移后的 equal 句仍保留。只有重排、缺少可定位锚点或无法安全分离的结构变化才拦截。对不上时整对象保留原德语及旧基线，标 `structure_mismatch`（德语未跟上：结构不同），不调用模型；重试和历史 force 参数不能绕过。机器译文校验成功即 `synced`，无需人工批准。暂时失败沿用 3 次尝试、间隔 15 分钟；无密钥、不可重试或耗尽重试标 `failed`，保留旧译文。`needs_review` 不触发强制翻译；保留历史人工记录，不再产生审批状态。
- `RestLang`：`wp/v2/*` 与 `wc/store/v1/products` 列表按 `?lang=` 过滤（默认 en）；按 slug 取单品按语言；响应带 `Vary: Cookie` 之外不依赖 cookie（LiteSpeed 只认 URL）。
- `WooSync`：SKU 与库存只在英文商品；德语商品 SKU 为空、`manage_stock` 关闭、价格与 `stock_status` 由 `pll_save_post_translations`/英文保存钩子单向镜像；购物车与订单行把德语商品 ID 映射为英文 ID、显示德语名；订单保存语言；Woo 邮件按订单语言发（`de_DE_formal` 语言包）；属性名走 gettext。
- `Admin`：产品、页面、博客的 EN/DE 后台列表共享英文源的德语状态：已同步 / 等待翻译 / 翻译失败 / 结构不同 / 缺失，权限和 nonce 保护的重译入口；无其他后台页面。
- 字符串：所有插件 UI 文案用 `__()`，`.pot/.po/.mo` + `wp i18n make-json`；不再有 7 套机制。

## 迁移 `tools/migrate/9-i18n.py`（本地实例演练，切换时随 #17 执行）
1. 安装 Polylang，施加配置；把全部现有内容设为 en（不设则前台不显示）。
2. 建德语分类、属性词（来源 `shelf-slugs-de.json`、`taxonomy-de.json`）。
3. 为 27 页、10 文、106 商品建德语版（先插入、设语言、再改 slug；来源 `_linker_de_*`、`wp_linker_string`、slug 映射）。~~页眉页脚模板同法~~ → **2026-10-15 翻案（票 #182）**：lc_partial/lc_dynamic_template 已从迁移的 TRANSLATED_TYPES 移除——它们的德语孪生内容归仓库展示层（`present`）所有，迁移写入会成为第二写者并覆盖刚部署的内容（当日事故：德语页头/页脚/三个页面型模板被旧站负载覆盖，德语 PDP/归档/博客回退旧实现）。这些对象的配对由 `linker-i18n repair-partials` 负责，内容只由 `present` 写。**顺序铁律：`present` 必须在迁移之后无条件再跑一次（或跑在最后）**。
4. 正文内链接改写为德语地址；SEOPress meta 迁移。
5. 验证 150 个德语 URL。
回滚：德语版撤为草稿 → 停用 Polylang → 重新激活旧 linker-i18n（只在切换窗口内有效）。

## 风险（必须在实现中逐条处理）
同 slug 查错语言；分类先设语言再建；库存镜像只处理英文；后台 REST 默认只返回英文；LiteSpeed 按 cookie 缓存 → 语言只在 URL；`Linker_I18n_Lang::` 旧接口不复刻。

## 验收
- [ ] 本地：150 个德语 URL 全部 200 且德语在服务端 HTML；`/de/about/` 这类英文段 404；hreflang、canonical、德语 sitemap 正确。
- [ ] 改一件英文商品描述 → 任务后德语版更新；只翻英文改动且能对齐的句子，其他人工德语逐字节保留；无基线先收养，结构不同保留并显性报异常，成功后直接 synced。
- [ ] ERP 按 SKU 推一次库存 → 两种语言同时变化；德语下提交询盘 → 订单行指向英文商品、名称德语、订单语言 de、邮件德语 Sie 体。
- [ ] `wc/store/v1/products?lang=de` 返回德语名称、描述、分类与链接。
- [ ] 视觉验收：产品页、分类页、询盘提交页、账户页 EN/DE × 1440/390。

修订（2026-10-10，评审发现）：`wp linker-i18n setup` 建 de 语言时，Polylang 会给每个带 `default_<taxonomy>` 选项的分类法（WordPress 的 `category`、WooCommerce 的 `product_cat`）自动建一个德语默认术语（"Uncategorized"，slug 如 `uncategorized-de`；Polylang `src/default-term.php`）。`category` 的在建语言时产生，`product_cat` 的还会在 `default_product_cat` 选项被更新时再产生。它们的归档不属于站点德语 URL，迁移 verify 会报 BAD；setup 现在每次运行都删除空的德语默认术语（英文侧默认术语保留），迁移 apply 走 setup，#17 切换日同一路径，切换后若改过 Woo 默认分类设置则重跑一次 setup。

修订（2026-10-14，线上复核轮缺陷族 16/22）：文章分类的德语词项 slug 取线上德语归档实际应答的 slug（system-design、battery-storage-blog、installation-commissioning、monitoring-energy-management、applications-blog；实测见 docs/debt/DE-PARITY-2026-10-13.md §4.1：/de/category/system-design/ 是 200 de-DE、Systemauslegung，systemauslegung 是 404）——与英文词项同 slug，靠 `SameSlug\TermSlugs`（词项有语言后允许；商品分类 ems-monitoring 先例）落库，Polylang canonical 对请求语言持有的同 slug 词项不跳转。按德文名造 slug（systemauslegung）会让 Polylang 301 回英文页。分类关系不在导入时从实例库抄（线上库这些行已不在）：迁移 apply 在导入后跑 `wp linker-i18n repair-post-categories`，从快照清单（posts 551–560 → terms 10–14）写回，英文文章与德语孪生各写一次；写之前核文章类型、词项语言与词项 slug（POST_CATEGORY_SLUGS），replace 不 append（558 挂在 Uncategorized 上时 append 会两边都留）。

修订（2026-10-15，评审轮）：`repair-post-categories` 的落库判据——写 0 篇（守卫不成立：库不是这份快照）以 `WP_CLI::error` 非零退出，成功消息报 `restored for N of the snapshot's 10 posts`；部署后读这条消息核对（de-sitemap 不含文章分类归档，迁移 verify 的 150 地址覆盖不到这个面）。部分写入（1–9 篇）仍是成功返回并报出 N。

修订（2026-10-15，清账决策 4）：运行钩子（`Twins::post()` 与 `Twins::term()` → `assign_term()` 的 restore 调用）改为 **fill-only**——只在文章当前没有任何分类时（英文文章与其德语孪生两侧都空，`get_the_terms` 判空）才从快照写回；任一侧已挂分类（人工编辑或既往修复）即跳过，编辑自由不受后续翻译影响。迁移修复的权威不变：`wp linker-i18n repair-post-categories` 仍全量写（不看现行分类、replace 语义不变），迁移 apply 与 #17 切换日的读回判据照旧。

修订（2026-10-16，欠账 N4）：404 页的 `<title>` 按请求语言。SEOPress 的 404 标题是全站单条选项（`seopress_titles_archives_404_title` = `Page not found %%sep%% %%sitetitle%%`），占位符在过滤前已替换成 `Page not found | Linker`，德语语言包到不了它——该句是 WordPress 核心自己的 404 兜底句，德语包里有 "Seite nicht gefunden"。`Seo::not_found_title` 挂在 `seopress_titles_title` 上，用核心句（"default" 文本域，locale 由 Polylang 逐请求切换）替换标题前缀，后缀（站点名）不动；非 404 与不含该句的标题原样返回。此前在 `docs/debt/DE-PARITY-2026-10-13.md` §2 记为缺口。

修订（2026-10-16，欠账 P3，评审在实例上查到）：**不透明块元素的文本属性不再被英文原文盖掉**。`Segmenter` 把 `video/audio/canvas/object/template/select/pre` 整段当原文块（内容保留是对的——里面的 source/track 不该翻），但整段也吞掉了元素自己的 `aria-label/alt/title/placeholder`：一次 TranslateOnSave 运行把德语页从英文源重建时，这些属性位按英文原文的字节写出。实测（`nbatch` 快照实例，2026-10-16）：`linker_i18n_translate` 为源 2748 跑完后，德语页 6700 的两个 stage video 从 `aria-label="Systemauslegung und Kompatibilitätslisten"` / `Systemauslegung mit Lösungskonfigurator` 变成英文 `System sizing and compatibility lists` / `Solution Configurator system sizing`，同一页其余德语一字未动（revision 7115 由 12-site-chrome apply 写于 14:13:39，revision 7128 由该任务写于 14:29:34，Action Scheduler 日志 9727 对齐）。修法：不透明块仍整块保留**内容**，但起始标签走普通分派——它的文本属性成为段（`Segmenter::HTML` 的分支），`TagPart::render` 同时接受 verbatim（已知德语字节）而不只是新翻译（`Document::render` 把 verbatim 一并传入）。回归测试 `SegmenterTest::test_an_opaque_blocks_attributes_are_segments`（旧代码上红：视频的 aria-label 不是段；新代码上绿：无翻译时逐字节往返、有翻译或 verbatim 时换值）。
**副产物（记录在案）**：修好后，凡记录态早于本次变更的德语页，其段数与记录不符，下一次英文保存会走 `Planner::absorb` 的 `'*'` 分支——整字段判为人工编辑、原样保留并标 needs_review，不再机器重写。这是安全侧（宁可保留德语、等人过目），也是 TranslateOnSave 在生产 dormant（无 DeepSeek key）下唯一可见的形态。


## 自动生效与上线（业主 2026-10-17 补充裁定，票 #253）

- 页面无营销冻结名单；人工译文审阅和批准步骤取消。上文历史 `needs_review` 不再强制重译：已有德语先保留，无基线只建基线，无法对齐保留并显性显示结构异常（PR 第一轮评审中的业主补充裁定）。
- `TranslatedTypes::POST_TYPES` 只含 page/post/product；`PRESENT_TYPES` 两类 LC 模板仅登记在 Polylang。保存、显式重译和任务执行都拒绝它们。
- 密钥优先级：`getenv(DEEPSEEK_API_KEY)` → `$_ENV` → `$HOME/.config/terravolt-builder/deepseek.env`。只解析键值，不执行文件；生产固定 `https://api.deepseek.com/chat/completions` / `deepseek-flash`，本地假端点只允许 local/development 的 loopback。
- `wp linker-i18n retire-template-jobs --user=<admin>` 只取消模板的 pending 任务并删除其状态/注记；内容、修订、语言组、展示 meta 不变。幂等；部署安全代码后、放生产密钥前运行。
- `wp linker-i18n translate --pending` 只选 pending；`--missing` 只选缺失或 pending，`--all` 是其兼容别名，不做全站重译。已有德语即使因 pending 入选也遵守保留/基线/改句/结构异常规则。历史 `--force` 仅兼容参数，不再覆盖人工德语；`--now` 失败或结构异常非零退出。异步保存期间源再次变化时补排后继任务。
- 摘要接口：`Linker\I18n\Translation\StatusReport::issues()` 返回 `list<array{kind: string, id: int, title: string, reason: string, edit_url: string}>`；只列英文源的最终 failed 或 structure_mismatch，不列模板、副本、正常排队和重试。每日摘要已合并，i18n 的 `Translation\DigestBlock` 经既有 `linker_commerce_digest_blocks` / `Digest\Block` 接入：数量、对象名、原因、英文源编辑链接和空态；在邮件 locale 下查询与渲染。commerce 接口不存在时不实例化该块，i18n 未启用则无过滤器；收件人、调度及发信继续归 commerce。
- 线上已知 20 pending = 14 模板状态清理 + 6 页面补译（Products、Cart、Proforma request、My account、Imprint、Solution Configurator）；随后 `--missing` 只补缺失和 pending，逐项读回；已有人工德语原样保留，只翻能对齐的改动句子，不做全站重译。
- 生产部署与密钥写入在评审合并后另获业主同意，备份后写、再读回；回滚旧代码之前先撤回新密钥。线上网页保存英文产品、异步官方翻译、前台德语更新及模板选择均须实证。

基线经现有 reviewed-page pair writer 按当前原文和元数据前像事务保存，
