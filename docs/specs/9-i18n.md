# #9 i18n：Polylang 免费版 + linker-i18n

依据：`docs/research/2026-10-09/i18n-opensource-replication.md`（功能清单与风险）、AGENTS.md §3（用词与 Sie 体）。

## Polylang 配置（由 `tools/local` 与切换脚本经 WP-CLI/REST 施加，不手点）
语言：en（默认，无前缀）、de（`/de/`，locale `de_DE_formal`）；URL 目录模式；浏览器语言检测关闭；同步：分类、标签、特色图、页面属性、菜单顺序、评论状态；媒体不翻译；字符串翻译开启。

## `plugins/linker-i18n`（PSR-4 `Linker\I18n\`，一类一文件）
- `SameSlug`：过滤 `wp_unique_post_slug` 与分类 slug，允许不同语言的翻译对使用同一 slug；按 slug 取单品/单页时按当前语言解析（修 `get_page_by_path`、Store API 按 slug 取单品）。
- `UrlSegments`：product → produkt、product-category → produkt-kategorie、shop 页 products → produkte；德语重写规则 + 反向解析；`/de/` 下的英文段返回 404（不再 200 重复页）。
- `TranslateOnSave`：英文对象保存（页面、文章、商品、分类、属性词、SEOPress meta、LiveCanvas 页眉页脚模板）→ 排队任务（Action Scheduler）→ 调 DeepSeek 逐段翻译（词表 `data/glossary-de.json` 强制、禁用词 `data/banned-de.json`、型号与数字保护、HTML 结构保护）→ 创建或更新德语版对象，写翻译组；译文带 `_linker_i18n_source_hash`，源文未变不重译；人工改过的德语段（`_linker_i18n_reviewed` 标记）不被覆盖，源文变化时标 `needs_review` 并在后台列表显示。
- `RestLang`：`wp/v2/*` 与 `wc/store/v1/products` 列表按 `?lang=` 过滤（默认 en）；按 slug 取单品按语言；响应带 `Vary: Cookie` 之外不依赖 cookie（LiteSpeed 只认 URL）。
- `WooSync`：SKU 与库存只在英文商品；德语商品 SKU 为空、`manage_stock` 关闭、价格与 `stock_status` 由 `pll_save_post_translations`/英文保存钩子单向镜像；购物车与订单行把德语商品 ID 映射为英文 ID、显示德语名；订单保存语言；Woo 邮件按订单语言发（`de_DE_formal` 语言包）；属性名走 gettext。
- `Admin`：产品与页面列表增加"德语：已同步 / 待审 / 缺失"列，一键重译；无其他后台页面。
- 字符串：所有插件 UI 文案用 `__()`，`.pot/.po/.mo` + `wp i18n make-json`；不再有 7 套机制。

## 迁移 `tools/migrate/9-i18n.py`（本地实例演练，切换时随 #17 执行）
1. 安装 Polylang，施加配置；把全部现有内容设为 en（不设则前台不显示）。
2. 建德语分类、属性词（来源 `shelf-slugs-de.json`、`taxonomy-de.json`）。
3. 为 27 页、10 文、106 商品建德语版（先插入、设语言、再改 slug；来源 `_linker_de_*`、`wp_linker_string`、slug 映射）。~~页眉页脚模板同法~~ → **2026-10-15 翻案（票 #182）**：lc_partial/lc_dynamic_template 已从迁移的 TRANSLATED_TYPES 移除——它们的德语孪生内容归仓库展示层（`present`）所有，迁移写入会成为第二写者并覆盖刚部署的内容（当日事故：德语页头/页脚/三个页面型模板被旧站负载覆盖，德语 PDP/归档/博客回退旧实现）。这些对象的配对由 `linker-i18n repair-partials` 负责，内容只由 `present` 写。**顺序铁律：`present` 必须在迁移之后无条件再跑一次（或跑在最后）**。
4. 正文内链接改写为德语地址；SEOPress meta 迁移。
5. 验证 150 个德语 URL。
回滚：德语版撤为草稿 → 停用 Polylang → 重新激活旧 linker-i18n（只在切换窗口内有效）。

## 风险（必须在实现中逐条处理）
同 slug 查错语言；分类先设语言再建；库存镜像只处理英文；后台 REST 默认只返回英文；LiteSpeed 按 cookie 缓存 → 语言只在 URL；`Linker_I18n_Lang::` 旧接口不复刻。

## 验收
- [ ] 本地：150 个德语 URL 全部 200 且德语在服务端 HTML；`/de/about/` 这类英文段 404；hreflang、canonical、德语 sitemap 正确。
- [ ] 改一件英文商品描述 → 任务后德语版更新；人工改过的德语段不被覆盖且标 needs_review。
- [ ] ERP 按 SKU 推一次库存 → 两种语言同时变化；德语下提交询盘 → 订单行指向英文商品、名称德语、订单语言 de、邮件德语 Sie 体。
- [ ] `wc/store/v1/products?lang=de` 返回德语名称、描述、分类与链接。
- [ ] 视觉验收：产品页、分类页、询盘提交页、账户页 EN/DE × 1440/390。

修订（2026-10-10，评审发现）：`wp linker-i18n setup` 建 de 语言时，Polylang 会给每个带 `default_<taxonomy>` 选项的分类法（WordPress 的 `category`、WooCommerce 的 `product_cat`）自动建一个德语默认术语（"Uncategorized"，slug 如 `uncategorized-de`；Polylang `src/default-term.php`）。`category` 的在建语言时产生，`product_cat` 的还会在 `default_product_cat` 选项被更新时再产生。它们的归档不属于站点德语 URL，迁移 verify 会报 BAD；setup 现在每次运行都删除空的德语默认术语（英文侧默认术语保留），迁移 apply 走 setup，#17 切换日同一路径，切换后若改过 Woo 默认分类设置则重跑一次 setup。

修订（2026-10-14，线上复核轮缺陷族 16/22）：文章分类的德语词项 slug 取线上德语归档实际应答的 slug（system-design、battery-storage-blog、installation-commissioning、monitoring-energy-management、applications-blog；实测见 docs/debt/DE-PARITY-2026-10-13.md §4.1：/de/category/system-design/ 是 200 de-DE、Systemauslegung，systemauslegung 是 404）——与英文词项同 slug，靠 `SameSlug\TermSlugs`（词项有语言后允许；商品分类 ems-monitoring 先例）落库，Polylang canonical 对请求语言持有的同 slug 词项不跳转。按德文名造 slug（systemauslegung）会让 Polylang 301 回英文页。分类关系不在导入时从实例库抄（线上库这些行已不在）：迁移 apply 在导入后跑 `wp linker-i18n repair-post-categories`，从快照清单（posts 551–560 → terms 10–14）写回，英文文章与德语孪生各写一次；写之前核文章类型、词项语言与词项 slug（POST_CATEGORY_SLUGS），replace 不 append（558 挂在 Uncategorized 上时 append 会两边都留）。

修订（2026-10-15，评审轮）：`repair-post-categories` 的落库判据——写 0 篇（守卫不成立：库不是这份快照）以 `WP_CLI::error` 非零退出，成功消息报 `restored for N of the snapshot's 10 posts`；部署后读这条消息核对（de-sitemap 不含文章分类归档，迁移 verify 的 150 地址覆盖不到这个面）。部分写入（1–9 篇）仍是成功返回并报出 N。

修订（2026-10-15，清账决策 4）：运行钩子（`Twins::post()` 与 `Twins::term()` → `assign_term()` 的 restore 调用）改为 **fill-only**——只在文章当前没有任何分类时（英文文章与其德语孪生两侧都空，`get_the_terms` 判空）才从快照写回；任一侧已挂分类（人工编辑或既往修复）即跳过，编辑自由不受后续翻译影响。迁移修复的权威不变：`wp linker-i18n repair-post-categories` 仍全量写（不看现行分类、replace 语义不变），迁移 apply 与 #17 切换日的读回判据照旧。
