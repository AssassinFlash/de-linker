# Solution Configurator product identity

Owner clarification, 2026-10-23: explain Linker's contribution to the whole
system, rather than put the product's value statement on its map provider.
The product remains Solution Configurator / Lösungskonfigurator.

The visible product identity names Linker as its developer. A shared native
disclosure is available from the project list and every project workspace,
including mobile. It explains the project workflow implemented by Linker before
subordinate software/data credits. Opening it must not lose edits, change the
workspace, start a calculation, activate a map provider or issue a network call.
Use ordinary accessible HTML and the existing WindPress tokens/pipeline.

The current disclosure may describe the actual common project for site, energy
inputs and roof design; edit/save/recovery coordination; common plan/map/3D
geometry; and source/revision records. Each claim must map to current source and
acceptance evidence. It must not announce unaccepted calculation, equipment,
country release, compliance, report or accuracy capabilities as available.

The full goal still includes system calculations, released equipment selection,
bill of materials, report/PDF and site/commerce consumers. Their customer-facing
explanations become part of this same system identity when those features have
passed their own acceptance. This copy increment does not remove or replace them.

The owner reiterated on 2026-10-24 that the product explanation must describe
the whole system. Describe what Linker enables the customer to accomplish with
one project: site and roof inputs, solar/storage analysis, evidence-based
equipment decisions and a usable proposal with its parts/report and inquiry
handoff. These remain the complete delivery target; only accepted capabilities
are described as currently available. The contribution is the connected project
workflow, its decisions and deliverables, rather than a list of dependencies.

Apply that same product explanation to the accepted tool introduction, site
entry points and report identity as those surfaces are delivered. The shared
footer/disclosure is the persistent attribution and detailed-source access;
it is not the entire product introduction. Component credits retain their
specific roles within that overall Linker product identity.

Credits identify the role of each actual component/service. A map provider must
not be labelled as powering the whole configurator. Required map attribution
stays with the map; this disclosure is additional, not a replacement. Distinguish
software licences, data licences, provider/privacy conditions and declared input
quality. Do not imply external providers endorse Linker or validate its results.

EN is the source language; formal DE is independently written and reviewed.
Draft, opposition and final wording are retained in the existing acceptance
folder. Native EN/DE at 1440/390 verifies the shared disclosure, keyboard/native
toggle, wrapping, source links and intact project revision/input state.
