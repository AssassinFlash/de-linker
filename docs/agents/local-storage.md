# 本地存储保留与回收

依据：业主 2026-10-23 要求立即清理无用本地副本，授权执行者判断并删除明显过时的实例和备份，并将防止无限增长写入项目指令。业主 2026-10-29 进一步明确：备份必须有保留上限，任何资源创建前必须确定回收责任与条件，实例、进程、浏览器窗口／页面和临时文件用完立即回收，每次任务汇报必须包含资源报告。这些要求永久适用于所有会话，并优先于并行交付。

## 创建与回收合同

- 创建任何文件、备份、快照、工作树、实例、进程或浏览器窗口／页面前，在现有任务记录中写明绝对路径或资源标识、唯一用途、负责人、保留上限和回收条件；答不上来就不创建。新子代理也必须先声明资源预算和回收责任。
- 备份默认 `N=3`，按同一源环境、同类资源合并计数；重大改动前的临时恢复点只留 1 份，验证通过后立即删除。若其他保留规则冲突，采用更严格的边界，禁止“以防万一”式副本。
- 同时运行的实例、工作树、浏览器及标签页只保留当前实际验证所需的最小数量。每个交互或验证完成立即关闭对应页面和进程；暂停、限流、会话结束或任务收尾时同样执行，不以“之后可能有用”保留运行资源。
- 每次任务开始和收尾读回磁盘占用及可用空间；汇报本次新增、回收及实际释放量，说明仍需保留的资源和理由。收尾必须确认无遗留进程、无未关闭资源、无不再需要的临时文件。

## 保留边界

每次新增成功后和任务结束前执行淘汰。同类资源合并计数，改名称、日期或票号不能规避保留边界。

| 资源 | 默认保留范围 | 回收条件 |
| --- | --- | --- |
| 同一源环境的整站备份、独立数据库快照，分别计数 | 最近 3 份完整成功版本、最近 7 天每天最后 1 份、1 份明确的恢复基线；重复项只计一次 | 验证保留版本后删除范围外的旧版本 |
| 开发用线上快照 | 最近 3 份成功快照、1 份明确的恢复基线，以及进行中任务实际引用的版本 | 任务不再引用且超出上述范围即删除 |
| 开发实例与临时工作树 | 每个进行中任务默认各 1 个；确需基线对照时可各加 1 个，并记录用途和回收条件 | 任务合并、验收已被接受或明确废弃后回收；后续验证优先复用已有合适环境 |
| 失败或中断的备份 | 正在重试或排障的版本，有具体负责人和截止时间 | 已有完整成功版本接替且没有进行中的读写或排障依赖时删除 |
| 可重建依赖、缓存和重复评审副本 | 当前任务实际需要的内容 | 无活跃进程引用，且可由锁文件、源文件或已核实的原件重建时清理 |

需要临时超出默认范围时，在本票既有记录中写明绝对路径、唯一用途、负责人、具体到期时间和回收条件。到期复核；用途解除立即删除。只保留“可能有用”或没有负责人的副本不合格。独立数据库快照与整站备份一并纳入回收，不能另开目录无限积累。

## 新增前

- 读回实际磁盘可用空间，检查同机已有实例、快照和备份，优先复用本票满足验证状态的资源，保持各执行任务隔离；跨会话复用先确认原任务已释放。线上状态确已变化或隔离对照确有需要时再新增，并记录原因。
- 纯文档和只读审计无需新建站点、工作树依赖或整站快照。重复测试使用同一份已核实快照，避免每轮测试重新下载与复制全站。
- 生产写入仍按 `AGENTS.md` 第 5 节先备份。已有备份必须覆盖本次操作前的状态和回滚范围才可复用；新增必要恢复点后，在同一任务完成淘汰。
- 出现磁盘空间告警，或剩余空间不足以承载预计写入时，先停止非必要新增并清理。清理本身只保存小型登记元数据、删除清单和核验结果。
- **增量传输复用已验证的粒度。**插件目录已有完整 `link-dest`，且当前主机已有该目录整树增量传输成功的记录时，直接使用现成 `Target.rsync()` 的整树 `--link-dest` 路径；出现具体传输失败后再调整分块，避免为未变化的小文件逐个重建 SSH 连接。
- **中断从同一备份点续传。**先核实并停止本任务的传输进程，验证已完成数据库的哈希、压缩可读性和已传文件集，再只补剩余目录；沿用原清单格式完成其覆盖文件集的读回，不另建快照或重传已验证完成的原件。

## 删除前

- 核实资源用途、任务是否仍在进行、负责人当前保留清单、进程 PID 与启动身份、端口和数据库连接。进程仍在运行不等于任务仍需要它；确认废弃的运行实例须先安全停止。
- 检查保留备份的 manifest、数据库压缩包可读性、可用的哈希与恢复所需文件；核对仍在用的实例所引用的快照。先证明恢复点完整，再淘汰旧版本。
- 工作树整体删除前检查合并状态、受跟踪改动、未跟踪文件和被忽略的唯一原型或证据。未合并代码、未提交修改、唯一上传原件、唯一验收文件及唯一有效恢复点继续保留；可先只删除可重建依赖。
- 目录统计须考虑硬链接、APFS 共享及其他会话的读写；同时处理共享根目录时先协调分工和保留清单。不得根据目录名、日期或 `du` 数值单独决定删除。

## 删除与完成判定

- 按核实过的精确路径删除。实例回收包括停止已确认身份的进程、删除对应本地测试数据库和实例文件、在登记表锁内移除登记项；保护其他会话及其他数据库。
- 实例回收同时清理其 Redis 对象缓存。依据 `tools/local/src/linker_local/objectcache.py` 的精确前缀 `linker_<实例名>:`，在确认退役、目录和数据库均已移除后，用 `SCAN` 分批定位并 `UNLINK` 回收；每批重读登记表，跳过仍登记或新复用的实例，保留归属未知的前缀。禁止对共享库执行 `FLUSHDB` / `FLUSHALL`。完成后核验退役前缀已无残留、保留实例仍可访问；只保存小型数量清单，不备份可重建缓存。依据：2026-10-23 实测已删实例仍遗留约 93 万条缓存、占用约 1.34 GiB，见本机性能清理报告。
- 数据库日志通过数据库自身的清理机制处理，保持数据库运行文件完整。
- 删除后读回实际可用空间；检查已删目录、对应数据库和登记项确实消失，保留的快照引用仍有效，正在工作的环境仍可访问。移动到废纸篓不算释放空间。
- 交付时报告实际空间增量、删除数量、保留范围与核验结果；未完成回收不能把“建议以后清理”当作交付。
